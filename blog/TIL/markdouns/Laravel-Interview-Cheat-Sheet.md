# 📚 چیت‌شیت جامع مصاحبه لاراول - یک ساعت مانده به مصاحبه

> **هدف این چیت‌شیت**: مرور سریع مفاهیم کلیدی با توضیحات مفهومی، نه صرفاً حفظ کردن. هر پاسخ شامل **مفهوم اصلی** و **نکته کاربردی** است.

---

## 🗄️ بخش ۱: MySQL

### ۱. تفاوت INNER JOIN و LEFT JOIN و RIGHT JOIN چیست؟

**مفهوم**: JOINها برای ترکیب داده‌های چند جدول بر اساس رابطه بین آنها استفاده می‌شوند.

- **INNER JOIN**: فقط رکوردهایی که در **هر دو جدول** تطابق دارند را برمی‌گرداند. مانند اشتراک دو مجموعه.
- **LEFT JOIN**: **همه** رکوردهای جدول چپ + رکوردهای منطبق از جدول راست. اگر تطابقی نباشد، ستون‌های جدول راست NULL می‌شوند.
- **RIGHT JOIN**: برعکس LEFT JOIN؛ همه رکوردهای جدول راست + رکوردهای منطبق از جدول چپ.

> **نکته کاربردی**: در اکثر موارد از LEFT JOIN استفاده می‌شود و RIGHT JOIN کمتر کاربرد دارد (چون می‌توانید جدول‌ها را عوض کنید).

### ۲. Index چیست؟ B-Tree Index چطور کار می‌کند؟

**مفهوم**: Index ساختاری داده‌ای است که جستجوی رکوردها را در دیتابیس سریع‌تر می‌کند، درست مانند فهرست کتاب.

- **B-Tree**: یک درخت متعادل که داده‌ها را **مرتب** نگه می‌دارد. هر گره می‌تواند چندین کلید داشته باشد.
- جستجو با **O(log n)** انجام می‌شود: از ریشه شروع، مقایسه می‌کند و به شاخه مناسب می‌رود.
- برای جستجوی دقیق، محدوده (BETWEEN) و مرتب‌سازی (ORDER BY) عالی است.

> **نکته کاربردی**: Index روی ستون‌هایی که زیاد در WHERE و JOIN استفاده می‌شوند ایجاد کنید. زیاد بودن Index باعث کندی INSERT/UPDATE می‌شود.

### ۳. تفاوت Clustered و Non-clustered Index چیست؟

**مفهوم**: تفاوت در نحوه ذخیره‌سازی داده‌ها و Indexها در دیسک.

- **Clustered Index**: خود **ردیف‌های داده** بر اساس کلید Index مرتب و ذخیره می‌شوند. هر جدول فقط **یک** Clustered Index دارد (معمولاً Primary Key).
- **Non-clustered Index**: یک ساختار جداگانه که شامل کلید Index و **اشاره‌گر** به مکان داده در جدول است. یک جدول می‌تواند چندین Non-clustered Index داشته باشد.

> **نکته کاربردی**: Clustered Index جستجوی محدوده را بسیار سریع می‌کند ولی درج جدید ممکن است باعث بازآرایی (Page Split) شود.

### ۴. تفاوت WHERE و HAVING چیست؟

**مفهوم**: هر دو برای فیلتر کردن استفاده می‌شوند، اما در زمان‌های مختلف اجرا می‌شوند.

- **WHERE**: ردیف‌ها را **قبل از** GROUP BY فیلتر می‌کند. روی ستون‌های معمولی اعمال می‌شود.
- **HAVING**: گروه‌ها را **بعد از** GROUP BY فیلتر می‌کند. روی توابع تجمیعی (SUM, COUNT, AVG) اعمال می‌شود.

```sql
-- WHERE: قبل از گروه‌بندی
SELECT * FROM orders WHERE amount > 100;

-- HAVING: بعد از گروه‌بندی
SELECT user_id, SUM(amount) as total 
FROM orders 
GROUP BY user_id 
HAVING total > 1000;
```

> **نکته کاربردی**: همیشه از WHERE برای فیلترهای ساده استفاده کنید چون عملکرد بهتری دارد.

### ۵. تفاوت DELETE، TRUNCATE و DROP چیست؟

**مفهوم**: سه روش مختلف برای حذف داده با سطوح متفاوت.

| عملیات | سرعت | قابلیت Rollback | قفل | Auto Increment |
|--------|------|-----------------|-----|----------------|
| **DELETE** | کند | بله (در تراکنش) | Row Lock | تنظیم مجدد نمی‌شود |
| **TRUNCATE** | سریع | خیر (DDL) | Table Lock | تنظیم مجدد می‌شود |
| **DROP** | بسیار سریع | خیر | Table Lock | کل جدول حذف می‌شود |

- **DELETE**: شرطی است و می‌توانید با WHERE مشخص کنید. **لاگ می‌شود**.
- **TRUNCATE**: **همه** ردیف‌ها را حذف می‌کند بدون شرط، ساختار جدول باقی می‌ماند.
- **DROP**: کل **جدول** (ساختار + داده) را حذف می‌کند.

> **نکته کاربردی**: برای پاک کردن سریع همه داده‌ها از TRUNCATE استفاده کنید (غیرقابل بازگشت).

### ۶. ACID چیست و MySQL چطور آن را تضمین می‌کند؟

**مفهوم**: چهار ویژگی اصلی برای تضمین صحت تراکنش‌ها در دیتابیس.

- **Atomicity (اتمی)**: تراکنش یا کامل انجام می‌شود یا هیچ‌کدام. MySQL با **Undo Log** (برای بازگشت) تضمین می‌کند.
- **Consistency (سازگاری)**: دیتابیس از یک حالت معتبر به حالت معتبر دیگر می‌رود. با **قوانین (Constraints)** و **تراکنش‌ها** تضمین می‌شود.
- **Isolation (انزوا)**: تراکنش‌های همزمان روی هم تأثیر نمی‌گذارند. با **قفل‌ها (Locks)** و **MVCC** (Multi-Version Concurrency Control) تضمین می‌شود.
- **Durability (دوام)**: بعد از commit، تغییرات پایدار می‌مانند. با **Redo Log** و ذخیره در دیسک تضمین می‌شود.

> **نکته کاربردی**: InnoDB موتور پیش‌فرض MySQL است که از ACID پشتیبانی کامل می‌کند.

### ۷. Transaction Isolation Levels را توضیح دهید (دیفالت InnoDB چیست؟)

**مفهوم**: سطح انزوا مشخص می‌کند تراکنش‌ها چقدر از هم جدا هستند و چه مشکلاتی ممکن است رخ دهد.

| سطح | Dirty Read | Non-Repeatable Read | Phantom Read |
|-----|------------|---------------------|--------------|
| **READ UNCOMMITTED** | ✅ ممکن است | ✅ ممکن است | ✅ ممکن است |
| **READ COMMITTED** | ❌ | ✅ ممکن است | ✅ ممکن است |
| **REPEATABLE READ** | ❌ | ❌ | ✅ ممکن است (در InnoDB با MVCC جلوگیری می‌شود) |
| **SERIALIZABLE** | ❌ | ❌ | ❌ |

- **READ UNCOMMITTED**: تراکنش می‌تواند داده‌های **ناتمام** تراکنش دیگر را بخواند (خطرناک).
- **READ COMMITTED**: فقط داده‌های **کامیت شده** خوانده می‌شوند.
- **REPEATABLE READ**: **دیفالت InnoDB**. همان داده‌ها در طول تراکنش ثابت می‌مانند.
- **SERIALIZABLE**: بالاترین سطح، تراکنش‌ها سریالی اجرا می‌شوند (کندترین).

> **نکته کاربردی**: REPEATABLE READ تعادل خوبی بین عملکرد و سازگاری است.

### ۸. N+1 Query Problem چیست و چطور تشخیص می‌دهید؟

**مفهوم**: وقتی برای هر رکورد از مجموعه اصلی، یک کوئری اضافی برای رابطه ارسال می‌شود.

**مثال**:
```php
// N+1 Problem
$users = User::all();  // 1 query
foreach ($users as $user) {
    echo $user->posts->count();  // N queries (یکی برای هر کاربر)
}
// مجموع: 1 + N کوئری
```

**تشخیص**:
1. فعال کردن **Query Log** در Laravel: `DB::enableQueryLog()`
2. استفاده از **Laravel Debugbar** که تعداد کوئری‌ها را نشان می‌دهد.
3. بررسی زمان پاسخ‌گویی: اگر با افزایش داده‌ها، زمان به شدت افزایش یابد.

> **نکته کاربردی**: از **Eager Loading** با `with()` برای جلوگیری استفاده کنید.

### ۹. Normalization و Denormalization چه زمانی استفاده می‌شود؟

**مفهوم**: دو رویکرد مخالف در طراحی دیتابیس.

- **Normalization (نرمال‌سازی)**:
  - حذف افزونگی داده با تقسیم به جدول‌های کوچکتر
  - **مزیت**: یکپارچگی داده، به‌روزرسانی آسان، فضای کمتر
  - **معایب**: کوئری‌های JOIN بیشتر، کندتر خواندن
  - **کاربرد**: سیستم‌های **OLTP** (تراکنشی) مثل سیستم‌های مدیریت سفارش

- **Denormalization (دونرمال‌سازی)**:
  - افزودن داده‌های تکراری برای افزایش سرعت خواندن
  - **مزیت**: سرعت بالا، کوئری‌های ساده‌تر
  - **معایب**: فضای بیشتر، پیچیدگی به‌روزرسانی
  - **کاربرد**: سیستم‌های **تحلیلی** و **گزارش‌گیری** (Data Warehouse)

> **نکته کاربردی**: معمولاً با نرمال‌سازی شروع کنید و در صورت نیاز به عملکرد، بخش‌هایی را دونرمال کنید.

### ۱۰. چطور یک Query کند را دیباگ و بهینه می‌کنید؟ (EXPLAIN)

**مراحل**:

1. **EXPLAIN** را جلوی کوئری اضافه کنید:
```sql
EXPLAIN SELECT * FROM users WHERE email = 'test@example.com';
```

2. **ستون‌های مهم** را بررسی کنید:
   - **type**: از best به worst: `const` > `eq_ref` > `ref` > `range` > `index` > `ALL` (ALL = Table Scan = بد)
   - **possible_keys**: ایندکس‌های قابل استفاده
   - **key**: ایندکسی که واقعاً استفاده شده
   - **rows**: تعداد تخمینی ردیف‌ها (کمتر بهتر)
   - **Extra**: نکات مهم مثل `Using index` (خوب), `Using filesort` (بد), `Using temporary` (بد)

3. **راه‌حل‌ها**:
   - اضافه کردن **Index** روی ستون‌های WHERE و JOIN
   - بازنویسی کوئری برای استفاده از Index
   - کاهش داده‌ها با LIMIT
   - استفاده از **Covering Index** (همه ستون‌های مورد نیاز در Index)

### ۱۱. تفاوت Primary Key و Unique Key چیست؟

**مفهوم**: هر دو برای منحصر‌به‌فرد بودن استفاده می‌شوند.

| ویژگی | Primary Key | Unique Key |
|-------|-------------|------------|
| **تعداد در جدول** | فقط یک عدد | چندین عدد |
| **مقدار NULL** | ❌ غیرمجاز | ✅ مجاز (فقط یک NULL در MySQL) |
| **Clustered Index** | ✅ به طور پیش‌فرض | ❌ Non-clustered |
| **ارجاع خارجی (FK)** | ✅ می‌تواند هدف FK باشد | ✅ می‌تواند هدف FK باشد |
| **تغییرپذیری** | ❌ نباید تغییر کند | ✅ می‌تواند تغییر کند |

> **نکته کاربردی**: از Primary Key برای شناسه اصلی جدول استفاده کنید. از Unique برای ستون‌هایی مثل ایمیل یا کد ملی.

### ۱۲. Deadlock چیست و چطور جلوی آن را می‌گیرید؟

**مفهوم**: دو یا چند تراکنش منتظر قفل‌های یکدیگر هستند و هیچ‌کدام پیشرفت نمی‌کنند.

**مثال**:
```
تراکنش A: قفل روی جدول 1 → منتظر جدول 2
تراکنش B: قفل روی جدول 2 → منتظر جدول 1
→ بن‌بست (Deadlock)
```

**پیشگیری**:
1. **ترتیب ثابت** برای قفل‌گیری: همیشه جدول‌ها را به یک ترتیب قفل کنید.
2. **کاهش زمان تراکنش**: تراکنش‌ها را کوتاه و سریع نگه دارید.
3. **استفاده از `LOCK TABLES`** با احتیاط.
4. **تنظیم `innodb_lock_wait_timeout`** برای پایان دادن خودکار به تراکنش‌های طولانی.
5. **استفاده از READ COMMITTED** به جای REPEATABLE READ در صورت نیاز.

> **نکته کاربردی**: InnoDB به طور خودکار Deadlock را تشخیص و یکی از تراکنش‌ها را Rollback می‌کند. کد شما باید برای مواجهه با این خطا آماده باشد.

### ۱۳. تفاوت VARCHAR و TEXT چیست؟

**مفهوم**: دو نوع داده برای ذخیره رشته‌ها.

| ویژگی | VARCHAR | TEXT |
|-------|---------|------|
| **حداکثر طول** | 65,535 کاراکتر | 65,535 کاراکتر (TEXT) / 16MB (MEDIUMTEXT) / 4GB (LONGTEXT) |
| **ذخیره‌سازی** | در ردیف (row) ذخیره می‌شود | خارج از ردیف با اشاره‌گر (تا 768 بایت در ردیف) |
| **مقدار پیش‌فرض** | ✅ می‌تواند داشته باشد | ❌ نمی‌تواند |
| **ایندکس** | ✅ می‌تواند کامل ایندکس شود | ❌ فقط پیشوند (prefix) ایندکس می‌شود |
| **سرعت** | سریع‌تر (دسترسی مستقیم) | کندتر (نیاز به خواندن اضافی) |

> **نکته کاربردی**: برای رشته‌های کوتاه (مثل ایمیل، نام) از VARCHAR و برای متن‌های طولانی (مثل مقاله، توضیحات) از TEXT استفاده کنید.

## 📊 بخش ۲: Flowchart Diagram

### ۱۴. نماد بیضی (Oval) در فلوچارت به چه معناست؟

**مفهوم**: نشان‌دهنده **شروع** یا **پایان** یک فرآیند است.
- یک ورودی و یک خروجی دارد (یا هیچ‌کدام برای پایان).
- معمولاً حاوی عبارت "Start" یا "End" یا "Begin".

### ۱۵. نماد لوزی (Diamond) چه کاربردی دارد؟

**مفهوم**: نمایش **تصمیم‌گیری** یا **شرط** در فلوچارت.
- دارای **یک ورودی** و **دو خروجی** (معمولاً "Yes" و "No").
- بر اساس یک شرط، مسیر اجرا را تعیین می‌کند.
- معادل `if-else` در برنامه‌نویسی.

### ۱۶. نماد مستطیل (Rectangle) چیست؟

**مفهوم**: نمایش یک **عملیات** یا **پردازش**.
- شامل یک عمل خاص مثل محاسبه، تغییر داده یا فراخوانی تابع.
- دارای یک ورودی و یک خروجی است.
- رایج‌ترین نماد در فلوچارت‌ها.

### ۱۷. نماد متوازی‌الاضلاع (Parallelogram) برای چه استفاده می‌شود؟

**مفهوم**: نمایش **ورودی** یا **خروجی** داده.
- دریافت اطلاعات از کاربر (ورودی) یا نمایش نتایج (خروجی).
- معادل `read` و `print` یا `input/output`.

### ۱۸. نماد ذوزنقه (Trapezoid) به چه معناست؟

**مفهوم**: نمایش یک **عملیات دستی** که توسط انسان انجام می‌شود.
- به عنوان مثال: وارد کردن داده توسط کاربر، بررسی دستی یک سند.
- نشان‌دهنده جایی است که فرآیند از کنترل سیستم خارج می‌شود.

### ۱۹. Connector در فلوچارت چیست؟

**م概念**: نقطه‌ای برای **اتصال** بخش‌های مختلف فلوچارت.
- دو نوع: درون‌صفحه (همان صفحه) و برون‌صفحه (صفحه دیگر).
- از تکرار خطوط و شلوغی نمودار جلوگیری می‌کند.
- با حروف یا اعداد مشخص می‌شود.

### ۲۰. تفاوت Flowchart و Pseudocode چیست؟

**مفهوم**: دو روش مختلف برای نمایش الگوریتم.

| ویژگی | Flowchart | Pseudocode |
|-------|-----------|------------|
| **نوع نمایش** | گرافیکی و بصری | متنی و ساختاریافته |
| **درک** | آسان‌تر برای افراد غیربرنامه‌نویس | نزدیک‌تر به کد برنامه‌نویسی |
| **جزئیات** | کمتر (سطح بالا) | بیشتر (می‌تواند دقیق باشد) |
| **استفاده** | مستندسازی، آموزش | طراحی الگوریتم قبل از کدنویسی |

> **نکته کاربردی**: برای الگوریتم‌های ساده از فلوچارت و برای پیچیده‌تر از Pseudocode استفاده کنید.

### ۲۱. چطور یک الگوریتم ساده را با فلوچارت نمایش می‌دهید؟

**مراحل ساخت فلوچارت**:
1. **Start** (بیضی)
2. **ورودی** (متوازی‌الاضلاع) - دریافت داده
3. **عملیات** (مستطیل) - پردازش داده
4. **تصمیم** (لوزی) - بررسی شرط
5. بازگشت به مرحله ۳ یا ادامه
6. **خروجی** (متوازی‌الاضلاع) - نمایش نتیجه
7. **End** (بیضی)

**مثال**: الگوریتم محاسبه فاکتوریل
```
Start → Input n → i=1, fact=1 → i<=n? → (Yes) fact*=i, i++ → (No) Print fact → End
```

## 🚀 بخش ۳: Laravel

### ۲۲. چرخه‌ی زندگی یک Request در Laravel چگونه است؟

**مفهوم**: مسیر یک درخواست HTTP از ورود تا خروج در لاراول.

```
1. Request → public/index.php (ورودی همه درخواست‌ها)
2. HTTP Kernel (Kernel.php) بارگذاری می‌شود
3. Middlewareهای Global اجرا می‌شوند
4. Service Providers بارگذاری می‌شوند (bootstrap)
5. Routing مشخص می‌شود (مسیر مناسب پیدا می‌شود)
6. Middlewareهای Route (مخصوص مسیر) اجرا می‌شوند
7. Controller یا Closure (منطق اصلی) اجرا می‌شود
8. Response ساخته می‌شود (View/JSON/Redirect)
9. Middlewareهای پایان‌کار اجرا می‌شوند
10. Response به کلاینت ارسال می‌شود
```

> **نکته کاربردی**: این چرخه را برای Debugging مشکلات و افزودن عملکردهای سفارشی در نقاط مختلف درک کنید.

### ۲۳. Service Container چیست و چه کاربردی دارد؟

**مفهوم**: موتور اصلی **تزریق وابستگی** (DI) در لاراول. یک ظرف که تمام وابستگی‌های برنامه را مدیریت می‌کند.

**کاربردها**:
1. **تزریق وابستگی خودکار**: وقتی یک کلاس نیاز به وابستگی دارد، Container به‌طور خودکار آن را می‌سازد.
2. **Binding**: می‌توانید یک اینترفیس را به یک کلاس خاص متصل کنید.
```php
// Binding
app()->bind(PaymentInterface::class, ZarinpalService::class);

// Resolving
$payment = app()->make(PaymentInterface::class);
```
3. **Singleton**: یک نمونه واحد در کل برنامه.
```php
app()->singleton(SomeService::class, function($app) {
    return new SomeService($app->make(Dependency::class));
});
```

> **نکته کاربردی**: از Service Container برای کاهش وابستگی‌های سخت و افزایش تست‌پذیری استفاده کنید.

### ۲۴. تفاوت Service Provider و Service Container چیست؟

**مفهوم**: دو مفهوم مکمل اما متفاوت.

| Service Container | Service Provider |
|-------------------|------------------|
| **چه کاری** | موتور DI برای مدیریت وابستگی‌ها | ثبت سرویس‌ها در Container |
| **زمان** | همیشه در دسترس | در مرحله **bootstrap** اجرا می‌شود |
| **مکان** | در کل برنامه | در فایل `config/app.php` در بخش `providers` |
| **نمونه** | `app()->bind()`, `app()->make()` | `register()`, `boot()` |

- **Service Container**: می‌گوید **چگونه** سرویس ساخته شود.
- **Service Provider**: می‌گوید **چه** سرویسی در Container ثبت شود.

> **نکته کاربردی**: سرویس‌های خود را در Service Providerها ثبت کنید تا هنگام bootstrap برنامه در دسترس باشند.

### ۲۵. Middleware چیست و چه زمانی استفاده می‌شود؟

**مفهوم**: لایه‌های میانی که درخواست را قبل از رسیدن به کنترلر و پاسخ را قبل از ارسال به کلاینت فیلتر می‌کنند.

**کاربردها**:
1. **احراز هویت** (`auth`): بررسی لاگین بودن کاربر
2. **مجوزدهی** (`can`): بررسی دسترسی
3. **CORS**: مدیریت Cross-Origin requests
4. **Rate Limiting** (`throttle`): محدودیت درخواست
5. **Logging**: ثبت درخواست‌ها
6. **Maintenance Mode**: نمایش صفحه در حال بروزرسانی

**نحوه عملکرد**:
```php
public function handle($request, Closure $next) {
    // قبل از کنترلر
    $response = $next($request);
    // بعد از کنترلر
    return $response;
}
```

> **نکته کاربردی**: Middleware بهترین مکان برای logicهای cross-cutting است که در همه مسیرها تکرار می‌شوند.

### ۲۶. تفاوت Facade و Dependency Injection چیست؟

**مفهوم**: دو روش دسترسی به سرویس‌ها با مزایا و معایب مختلف.

| ویژگی | Facade | Dependency Injection |
|-------|--------|---------------------|
| **نحوه دسترسی** | استاتیک (`Cache::get()`) | از طریق constructor یا متد |
| **سادگی** | ✅ بسیار ساده و خوانا | ❌ نیاز به تنظیم بیشتر |
| **تست‌پذیری** | ❌ مشکل‌تر (نیاز به `shouldReceive`) | ✅ بسیار آسان (mock) |
| **شفافیت** | ❌ وابستگی‌ها پنهان می‌شوند | ✅ وابستگی‌ها مشخص هستند |
| **کاربرد** | برای سادگی و سریع‌نویسی | برای تست‌پذیری و maintainability |

```php
// Facade
Cache::put('key', 'value', 60);

// Dependency Injection
public function __construct(private CacheStore $cache) {}
$this->cache->put('key', 'value', 60);
```

> **نکته کاربردی**: برای پروژه‌های بزرگ از DI استفاده کنید تا تست‌پذیری و maintainability بالاتر رود.

### ۲۷. Event و Listener چطور کار می‌کنند؟ تفاوتشان با Observer چیست؟

**م概念**: سیستم رویدادمحور در لاراول برای جداسازی منطق برنامه.

**Event و Listener**:
- **Event**: یک رویداد خاص را تعریف می‌کند (مثلاً `OrderShipped`)
- **Listener**: به رویداد گوش می‌دهد و واکنش نشان می‌دهد
- نحوه کار: `event(new OrderShipped($order))` → Listenerها اجرا می‌شوند

**Observer (Eloquent Observer)**:
- نوع خاصی از Listener که به رویدادهای **مدل Eloquent** متصل است
- رویدادها: `creating`, `created`, `updating`, `updated`, `deleting`, `deleted`
- در کلاس Observer ثبت می‌شود

**تفاوت کلیدی**:
- **Event/Listener**: عمومی و برای هر بخشی از برنامه
- **Observer**: فقط برای رویدادهای مدل Eloquent

> **نکته کاربردی**: از Events برای جداسازی منطق و از Observers برای رویدادهای دیتابیس استفاده کنید.

### ۲۸. Job و Queue در Laravel چطور کار می‌کنند؟

**مفهوم**: سیستم پردازش **ناهمگام** (async) برای وظایف سنگین و طولانی.

**Job**:
- یک کلاس که منطق یک کار خاص را شامل می‌شود
- با `php artisan make:job` ساخته می‌شود
- متد `handle()` منطق اصلی را دارد

**Queue**:
- صفی که Jobها در آن قرار می‌گیرند
- درایورهای مختلف: `database`, `redis`, `beanstalkd`, `sqs`, `sync` (همزمان)

**نحوه کار**:
1. Job را به Queue اضافه کنید: `ProcessPodcast::dispatch($podcast)`
2. Worker آن را از Queue برمی‌دارد: `php artisan queue:work`
3. Job اجرا می‌شود و می‌تواند شکست بخورد یا مجدداً تلاش کند

> **نکته کاربردی**: از Queue برای ارسال ایمیل، پردازش تصاویر، API calls و گزارش‌گیری استفاده کنید.

### ۲۹. Repository Pattern و Service Layer در Laravel چه فایده‌ای دارند؟

**مفهوم**: دو الگوی معماری برای جداسازی لایه‌ها.

**Repository Pattern**:
- لایه انتزاع بین کنترلر و دیتابیس
- منطق دسترسی به داده (CRUD) در این لایه
- مزیت: تغییر دیتابیس (MySQL → MongoDB) بدون تغییر کنترلر
```php
interface UserRepository {
    public function findById($id);
    public function findByEmail($email);
}

class EloquentUserRepository implements UserRepository {
    // پیاده‌سازی با Eloquent
}
```

**Service Layer**:
- منطق **کسب‌وکار** (Business Logic) در این لایه
- ارتباط بین کنترلر و Repository
- کنترلر فقط درخواست را می‌گیرد و به Service می‌دهد
```php
class UserService {
    public function registerUser($data) {
        // اعتبارسنجی، پردازش، ذخیره، ارسال ایمیل
    }
}
```

> **نکته کاربردی**: کنترلرها باید لاغر (thin) باشند و منطق اصلی در Service قرار گیرد.

### ۳۰. تفاوت Route Model Binding چیست و چطور کار می‌کند؟

**مفهوم**: تزریق خودکار مدل به کنترلر بر اساس پارامتر مسیر.

**نحوه کار**:
```php
// Route
Route::get('/users/{user}', [UserController::class, 'show']);

// Controller
public function show(User $user) {
    return $user; // لاراول به‌طور خودکار User با id مشابه را پیدا می‌کند
}
```

**انواع**:
1. **Implicit Binding**: بر اساس کلید اصلی، لاراول مدل را پیدا می‌کند
2. **Explicit Binding**: در `RouteServiceProvider` با `Route::model()` یا `Route::bind()` مشخص می‌شود
3. **Custom Resolution**: با `resolveRouteBinding()` در مدل برای منطق سفارشی

**Fail**:
- اگر مدل پیدا نشود، خطای 404 برمی‌گرداند

> **نکته کاربردی**: برای APIها و زمانی که می‌خواهید از منطق سفارشی برای یافتن مدل استفاده کنید، Explicit Binding مناسب است.

### ۳۱. Artisan Command چیست و چطور یک Command سفارشی می‌سازید؟

**مفهوم**: ابزار خط فرمان لاراول برای انجام وظایف مختلف.

**ساخت Command سفارشی**:


> **نکته کاربردی**: از Artisan برای cron jobs, data migration, maintenance tasks و توسعه استفاده کنید.

### ۳۲. Config Caching و Route Caching چه تفاوتی دارند و چه زمانی لازمند؟

**مفهوم**: دو نوع کش برای افزایش سرعت در محیط تولید.

**Config Caching**:
- `php artisan config:cache`
- تمام فایل‌های `config/` را در یک فایل ترکیب می‌کند
- استفاده: **تولید** (Production) - باعث افزایش سرعت بارگذاری تنظیمات
- در **توسعه** (Development) استفاده نکنید (تغییرات دیده نمی‌شود)

**Route Caching**:
- `php artisan route:cache`
- تمام مسیرها را در یک فایل سریالایز می‌کند
- استفاده: **تولید** - برای افزایش سرعت matching مسیر
- با `Route::group` و Closureها **کار نمی‌کند** (باید از کنترلرها استفاده کنید)

> **نکته کاربردی**: همیشه بعد از `php artisan config:cache` از `php artisan cache:clear` برای پاک کردن کش استفاده کنید.

### ۳۳. تفاوت Blade و API Resource چیست؟

**مفهوم**: دو روش مختلف برای نمایش داده.

**Blade**:
- موتور **رندر سمت سرور** (Server-side rendering)
- خروجی: HTML کامل
- کاربرد: وب‌سایت‌های سنتی و SPAهای با رندر سرور
```blade
<h1>{{ $user->name }}</h1>
@foreach($posts as $post)
    <div>{{ $post->title }}</div>
@endforeach
```

**API Resource**:
- تبدیل Eloquent مدل‌ها به **JSON ساختارمند**
- خروجی: JSON (برای APIها)
- کاربرد: RESTful APIs و اپلیکیشن‌های موبایل
```php
class UserResource extends JsonResource {
    public function toArray($request) {
        return [
            'id' => $this->id,
            'name' => $this->name,
            'posts' => PostResource::collection($this->whenLoaded('posts'))
        ];
    }
}
```

> **نکته کاربردی**: از Blade برای Frontend و از API Resource برای Backend/API استفاده کنید.

## 🔐 بخش ۴: Laravel Authentication

### ۳۴. تفاوت Session-based Authentication و Token-based Authentication چیست؟

**مفهوم**: دو رویکرد برای احراز هویت کاربر.

**Session-based**:
- **Stateful**: سرور **وضعیت** کاربر را ذخیره می‌کند (Session)
- ذخیره: کوکی (Cookie) روی کلاینت + داده در سرور
- کاربرد: وب‌سایت‌های سنتی با فرم ورود
- ویژگی: یکپارچه با Laravel's `auth` و `session`

**Token-based**:
- **Stateless**: سرور هیچ وضعیتی نگه نمی‌دارد
- ذخیره: توکن (JWT) در کلاینت، هر درخواست شامل توکن است
- کاربرد: APIها، اپلیکیشن‌های موبایل، میکروسرویس‌ها
- ویژگی: مقیاس‌پذیر، کار با دامنه‌های مختلف

> **نکته کاربردی**: برای APIها از Token-based و برای وب‌سایت‌های کامل از Session-based استفاده کنید.

### ۳۵. Sanctum چیست و در چه مواردی استفاده می‌شود؟

**مفهوم**: پکیج احراز هویت لاراول که هم برای **SPA** و هم **API** کار می‌کند.

**ویژگی‌ها**:
1. **SPA Authentication**: از کوکی‌ها و Session استفاده می‌کند (Stateful)
2. **API Tokens**: تولید توکن‌های ساده برای APIها (Stateless)
3. **Mobile Apps**: پشتیبانی از احراز هویت موبایل

**موارد استفاده**:
- اپلیکیشن‌های Vue/React با Backend لاراول (SPA)
- APIهای ساده که نیاز به OAuth2 ندارند
- اپلیکیشن‌های موبایل با توکن‌های ساده

> **نکته کاربردی**: Sanctum برای پروژه‌هایی که هم وب و هم API دارند، بهترین انتخاب است.

### ۳۶. تفاوت Sanctum و Passport چیست؟

**مفهوم**: دو پکیج برای احراز هویت با سطوح مختلف پیچیدگی.

| ویژگی | Sanctum | Passport |
|-------|---------|----------|
| **هدف اصلی** | SPA و API ساده | OAuth2 کامل |
| **پیچیدگی** | ساده و سبک | پیچیده و کامل |
| **توکن‌ها** | توکن‌های ساده API | OAuth2 Access/Refresh Tokens |
| **کلاینت‌های Third-party** | ❌ پشتیبانی نمی‌کند | ✅ پشتیبانی کامل |
| **مدیریت کلاینت** | ندارد | دارد (در دیتابیس) |
| **نصب** | ساده (یک دستور) | نیاز به migration و keys |
| **کاربرد** | پروژه‌های کوچک تا متوسط | سیستم‌های با چندین کلاینت مختلف |

> **نکته کاربردی**: برای پروژه‌های شخصی و SPAها از Sanctum استفاده کنید. برای سیستم‌های بزرگ با OAuth2 از Passport.

### ۳۷. Guard و Provider در سیستم Auth چه تفاوتی دارند؟

**مفهوم**: دو بخش اصلی سیستم احراز هویت لاراول.

**Guard**:
- مشخص می‌کند **چگونه** کاربر احراز هویت شود
- انواع: `web` (Session-based), `api` (Token-based), `sanctum`
- در `config/auth.php` تنظیم می‌شود
```php
'guards' => [
    'web' => ['driver' => 'session', 'provider' => 'users'],
    'api' => ['driver' => 'token', 'provider' => 'users'],
]
```

**Provider**:
- مشخص می‌کند داده‌های کاربر از **کجا** بیاید
- انواع: `eloquent` (مدل‌ها), `database` (جدول مستقیم)
- در `config/auth.php` تنظیم می‌شود
```php
'providers' => [
    'users' => [
        'driver' => 'eloquent',
        'model' => App\Models\User::class,
    ]
]
```

> **نکته کاربردی**: برای هر Guard یک Provider مشخص می‌کنید. می‌توانید چندین Guard و Provider داشته باشید.

### ۳۸. تفاوت Authentication و Authorization چیست؟

**مفهوم**: دو مفهوم مجزا در امنیت برنامه.

| Authentication (احراز هویت) | Authorization (مجوزدهی) |
|------------------------------|-------------------------|
| **چه کاری** | هویت کاربر را تأیید می‌کند | دسترسی کاربر را بررسی می‌کند |
| **پرسش** | "شما کی هستید؟" | "آیا مجاز به انجام این کار هستید؟" |
| **زمان** | اول (ورود) | بعد از Authentication |
| **مثال** | Login با ایمیل و رمز | کاربر Admin می‌تواند کاربران را حذف کند |
| **Laravel** | `Auth::check()` | `$user->can()` یا `Gate` |

> **نکته کاربردی**: Authentication پیش‌نیاز Authorization است. ابتدا کاربر را شناسایی کنید، سپس مجوزها را بررسی کنید.

### ۳۹. Gate و Policy چه تفاوتی دارند؟

**مفهوم**: دو روش برای تعریف مجوزها در لاراول.

**Gate**:
- تعریف **سراسری** و عمومی در `AuthServiceProvider`
- مناسب برای مجوزهایی که به مدل خاصی وابسته نیستند
```php
Gate::define('manage-users', function ($user) {
    return $user->isAdmin();
});
```

**Policy**:
- تعریف **مخصوص** یک مدل خاص
- منطق مجوز در یک کلاس جداگانه (برای هر مدل)
- با `php artisan make:policy UserPolicy` ساخته می‌شود
```php
class UserPolicy {
    public function delete(User $user, User $model) {
        return $user->isAdmin() || $user->id === $model->id;
    }
}
```

> **نکته کاربردی**: برای مجوزهای مرتبط با مدل از Policy و برای مجوزهای عمومی از Gate استفاده کنید.

### ۴۰. چطور یک API را بین سرویس‌ها (Service-to-Service) احراز هویت می‌کنید؟

**مفهوم**: احراز هویت در معماری میکروسرویس‌ها.

**روش‌ها**:
1. **API Keys**: کلید ساده در هدر `X-API-Key` - مناسب برای سرویس‌های داخلی
2. **JWT با امضای مشترک**: سرویس‌ها توکن JWT را با Secret Key امضا می‌کنند و بررسی می‌کنند
3. **OAuth2 Client Credentials**: برای ارتباط ماشین به ماشین
```http
POST /oauth/token
    grant_type=client_credentials
    client_id=XXX
    client_secret=XXX
```
4. **MTLS (Mutual TLS)**: احراز هویت دوطرفه با گواهی SSL
5. **Service Mesh**: مثل Istio با mTLS

> **نکته کاربردی**: برای سرویس‌های داخلی، JWT با Secret مشترک ساده و امن است.

### ۴۱. Middleware auth چطور کار می‌کند؟

**م概念**: بررسی می‌کند که کاربر وارد شده باشد یا خیر.

**نحوه عملکرد**:
```php
// Illuminate\Auth\Middleware\Authenticate
public function handle($request, Closure $next, ...$guards) {
    $this->authenticate($request, $guards);
    return $next($request);
}
```

**روند**:
1. مشخص می‌کند کدام Guard باید استفاده شود (از پارامترها)
2. `Auth::guard($guard)->check()` را صدا می‌زند
3. اگر **احراز نشده**:
   - API: 401 Unauthorized برمی‌گرداند
   - Web: به صفحه Login هدایت می‌کند (با `redirectTo`)
4. اگر **احراز شده**: درخواست ادامه پیدا می‌کند

**کاربرد**:
```php
Route::middleware('auth:api')->group(function() {
    // فقط کاربران وارد شده
});

Route::middleware('auth:sanctum')->group(function() {
    // برای SPA با Sanctum
});
```

> **نکته کاربردی**: برای APIها همیشه از `auth:api` با توکن استفاده کنید.

## 🗄️ بخش ۵: Laravel Eloquent

### ۴۲. تفاوت with() و load() چیست؟

**مفهوم**: دو روش برای Eager Loading روابط.

**with()**: بارگذاری در زمان ساخت Query
```php
// قبل از اجرا، رابطه بارگذاری می‌شود
$users = User::with('posts')->get();
// یک کوئری: Users + یک کوئری برای Posts
```

**load()**: بارگذاری بعد از دریافت مدل
```php
// ابتدا مدل‌ها گرفته می‌شوند
$users = User::all();
// سپس رابطه بارگذاری می‌شود
$users->load('posts');
// دو کوئری مجزا: Users + Posts
```

**تفاوت کلیدی**:
- `with()`: به Query Builder اضافه می‌شود
- `load()`: روی Collection اجرا می‌شود

> **نکته کاربردی**: از `with()` برای جلوگیری از N+1 و از `load()` برای بارگذاری شرطی استفاده کنید.

### ۴۳. Eager Loading چیست و چطور از N+1 جلوگیری می‌کند؟

**مفهوم**: بارگذاری روابط در **یک یا دو** کوئری اضافی به جای N+1 کوئری.

**مثال بدون Eager Loading (Lazy Loading)**:
```php
$users = User::all();  // 1 query
foreach ($users as $user) {
    echo $user->posts->count();  // N queries
}
// مجموع: N+1
```

**با Eager Loading**:
```php
$users = User::with('posts')->all();  // 2 queries
foreach ($users as $user) {
    echo $user->posts->count();  // بدون کوئری جدید
}
// مجموع: 2
```

**نحوه کار**:
- کوئری اول: همه کاربران
- کوئری دوم: همه پست‌ها با `whereIn('user_id', [1,2,3,...])`
- لاراول روابط را به هم متصل می‌کند

> **نکته کاربردی**: همیشه در حلقه‌ها و لیست‌ها از Eager Loading استفاده کنید.

### ۴۴. تفاوت whereHas و with چیست؟

**مفهوم**: دو متد متفاوت برای کار با روابط.

**whereHas**: فیلتر کردن مدل‌ها بر اساس **وجود** یا **شرط** در رابطه
```php
// فقط کاربرانی که حداقل یک پست دارند
User::whereHas('posts')->get();

// کاربرانی که پست با عنوان مشخص دارند
User::whereHas('posts', function($q) {
    $q->where('title', 'like', '%laravel%');
})->get();
```

**with**: بارگذاری **خود رابطه** برای استفاده بعدی
```php
// کاربران با پست‌هایشان بارگذاری می‌شود
User::with('posts')->get();
```

**ترکیب**:
```php
// هم فیلتر کنید و هم بارگذاری کنید
User::whereHas('posts')->with('posts')->get();
```

> **نکته کاربردی**: `whereHas` برای فیلتر کردن، `with` برای بارگذاری. با هم برای بهینه‌ترین کوئری.

### ۴۵. Accessor و Mutator چیستند؟

**مفهوم**: متدهایی برای تبدیل داده هنگام خواندن و نوشتن در مدل.

**Accessor** (getter):
- تبدیل خروجی ستون
- نام: `get{Attribute}Attribute`
```php
class User {
    public function getFullNameAttribute() {
        return $this->first_name . ' ' . $this->last_name;
    }
}
// استفاده: $user->full_name
```

**Mutator** (setter):
- تبدیل ورودی ستون
- نام: `set{Attribute}Attribute`
```php
class User {
    public function setPasswordAttribute($value) {
        $this->attributes['password'] = bcrypt($value);
    }
}
// استفاده: $user->password = 'secret'; // به‌طور خودکار هش می‌شود
```

**کاربرد Accessor**:
- فرمت‌بندی تاریخ، تبدیل JSON، محاسبه مقادیر مشتق
- ترکیب چند ستون

**کاربرد Mutator**:
- هش کردن رمز، تبدیل فرمت تاریخ، نرمال‌سازی داده

> **نکته کاربردی**: از `$casts` برای تبدیل‌های ساده و از Accessor/Mutator برای تبدیل‌های پیچیده استفاده کنید.

### ۴۶. تفاوت $fillable و $guarded چیست؟

**مفهوم**: دو روش برای محافظت در برابر Mass Assignment.

**$fillable**:
- لیست ستون‌هایی که **مجاز** به Mass Assignment هستند
```php
protected $fillable = ['name', 'email', 'password'];
```

**$guarded**:
- لیست ستون‌هایی که **غیرمجاز** به Mass Assignment هستند
- عکس $fillable
```php
protected $guarded = ['id', 'is_admin']; // همه به جز اینها مجازند
```

**Mass Assignment**:
- ایجاد/بروزرسانی با آرایه
```php
User::create($request->all()); // خطرناک!
User::create($request->only(['name', 'email'])); // ایمن با fillable
```

> **نکته کاربردی**: از `$fillable` استفاده کنید (لیست مجاز) تا امن‌تر باشد. از `$guarded` با احتیاط استفاده کنید.

### ۴۷. Mass Assignment Vulnerability چیست؟

**مفهوم**: حمله‌ای که کاربر می‌تواند فیلدهای حساس را از طریق فرم تغییر دهد.

**مثال حمله**:
```html
<form>
    <input name="name">
    <input name="email">
    <input name="is_admin" value="1" style="display:none">
</form>
```

**بدون محافظت**:
```php
User::create($request->all());
// کاربر is_admin = 1 را می‌فرستد و ادمین می‌شود!
```

**با محافظت**:
```php
// با $fillable
protected $fillable = ['name', 'email'];
// is_admin در لیست نیست → نادیده گرفته می‌شود

// یا با $guarded
protected $guarded = ['id', 'is_admin'];
// is_admin محافظت می‌شود
```

> **نکته کاربردی**: همیشه از Mass Assignment محافظت کنید، حتی در پروژه‌های کوچک.

### ۴۸. Soft Delete چطور کار می‌کند؟

**مفهوم**: حذف منطقی (حذف نشدن واقعی) با افزودن ستون `deleted_at`.

**فعال‌سازی**:
```php
use Illuminate\Database\Eloquent\SoftDeletes;

class User extends Model {
    use SoftDeletes;
}
// اضافه کردن ستون: $table->softDeletes()
```

**رفتار**:
- حذف: `$user->delete()` → `deleted_at` تنظیم می‌شود
- کوئری‌های عادی: فقط رکوردهای با `deleted_at IS NULL` را برمی‌گردانند
- بازیابی: `$user->restore()` → `deleted_at` NULL می‌شود
- حذف واقعی: `$user->forceDelete()`

**متدهای اضافی**:
- `withTrashed()`: همه رکوردها (شامل حذف شده)
- `onlyTrashed()`: فقط رکوردهای حذف شده
- `restore()`: بازیابی

> **نکته کاربردی**: برای داده‌های مهم و قابل بازیابی (مثل کاربران، سفارشات) از Soft Delete استفاده کنید.

### ۴۹. تفاوت save()، create()، firstOrCreate() و updateOrCreate() چیست؟

**مفهوم**: متدهای مختلف برای ذخیره مدل‌ها.

| متد | توضیح | مثال |
|-----|-------|------|
| **save()** | ذخیره مدل موجود (با/بدون تغییر) | `$user->save()` |
| **create()** | ایجاد و ذخیره مدل جدید | `User::create(['name'=>'John'])` |
| **firstOrCreate()** | پیدا یا ایجاد (if not exists) | `User::firstOrCreate(['email' => 'x@y.com'], ['name' => 'John'])` |
| **updateOrCreate()** | پیدا و بروزرسانی یا ایجاد | `User::updateOrCreate(['email' => 'x@y.com'], ['name' => 'John'])` |

**کاربرد**:
- `firstOrCreate`: برای جلوگیری از دوبرابری (مثل ثبت کاربر)
- `updateOrCreate`: برای بروزرسانی یا درج (مثل ذخیره تنظیمات)
- `create`: برای ایجاد جدید قطعی
- `save`: برای ذخیره تغییرات مدل موجود

> **نکته کاربردی**: `firstOrCreate` و `updateOrCreate` از Mass Assignment استفاده می‌کنند، پس `$fillable` را تنظیم کنید.

### ۵۰. رابطه‌های Eloquent را نام ببرید

**مفهوم**: انواع روابط بین مدل‌ها در لاراول.

**روابط یک‌به‌یک**:
- `hasOne()`: مدل فعلی یک مدل دیگر دارد
- `belongsTo()`: مدل فعلی متعلق به مدل دیگر است

**روابط یک‌به‌چند**:
- `hasMany()`: مدل فعلی چند مدل دیگر دارد
- `belongsToMany()`: مدل فعلی به چند مدل دیگر تعلق دارد (many-to-many)

**روابط چندبه‌چند**:
- `belongsToMany()`: با جدول pivot

**روابط Polymorphic**:
- `morphOne()`: یک مدل به چند نوع مختلف تعلق دارد
- `morphMany()`: چند مدل به چند نوع مختلف تعلق دارند
- `morphToMany()`: many-to-many polymorphic
- `morphedByMany()`: عکس morphToMany

**روابط از طریق**:
- `hasOneThrough()`: یک-به-یک از طریق یک واسطه
- `hasManyThrough()`: یک-به-چند از طریق یک واسطه

> **نکته کاربردی**: `belongsToMany` برای روابط many-to-many با جدول pivot استفاده می‌شود.

### ۵۱. تفاوت Lazy Loading و Eager Loading چیست؟

**مفهوم**: دو روش بارگذاری روابط در Eloquent.

| ویژگی | Lazy Loading | Eager Loading |
|-------|--------------|---------------|
| **زمان بارگذاری** | موقع دسترسی به رابطه | در زمان کوئری اصلی |
| **تعداد کوئری** | N+1 (برای هر رکورد یک کوئری) | 1 یا 2 کوئری |
| **عملکرد** | کند برای داده‌های زیاد | سریع برای داده‌های زیاد |
| **نحوه** | `$user->posts` | `User::with('posts')->get()` |
| **کنترل** | خودکار (در دسترسی) | دستی (با with یا load) |
| **N+1 Problem** | ✅ ایجاد می‌کند | ❌ جلوگیری می‌کند |

> **نکته کاربردی**: همیشه از Eager Loading برای لیست‌ها و حلقه‌ها استفاده کنید.

### ۵۲. Eloquent Events (creating, saving, ...) چه کاربردی دارند؟

**مفهوم**: رویدادهایی که در چرخه حیات مدل فعال می‌شوند.

**لیست رویدادها**:
- `creating`: قبل از ایجاد (INSERT)
- `created`: بعد از ایجاد
- `updating`: قبل از بروزرسانی (UPDATE)
- `updated`: بعد از بروزرسانی
- `saving`: قبل از ذخیره (INSERT یا UPDATE)
- `saved`: بعد از ذخیره
- `deleting`: قبل از حذف
- `deleted`: بعد از حذف
- `restoring`: قبل از بازیابی (Soft Delete)
- `restored`: بعد از بازیابی

**کاربردها**:
1. **اعتبارسنجی** (قبل از ذخیره)
2. **تولید کدهای منحصر‌به‌فرد** (در حال ایجاد)
3. **ارسال نوتیفیکیشن** (بعد از ایجاد یا بروزرسانی)
4. **ثبت لاگ** (در همه رویدادها)
5. **به‌روزرسانی کش** (بعد از تغییر)

```php
class User extends Model {
    protected static function booted() {
        static::creating(function ($user) {
            $user->uuid = Str::uuid();
        });
        
        static::updated(function ($user) {
            Cache::forget('user_' . $user->id);
        });
    }
}
```

> **نکته کاربردی**: از رویدادهای Model برای عملیات جانبی (side effects) استفاده کنید، منطق اصلی را در Service قرار دهید.

## 🗃️ بخش ۶: Redis و Cache

### ۵۳. تفاوت Redis و Memcached چیست؟

**مفهوم**: دو سیستم کش محبوب با ویژگی‌های متفاوت.

| ویژگی | Redis | Memcached |
|-------|-------|-----------|
| **نوع داده** | انواع: String, List, Hash, Set, Sorted Set | فقط Key-Value |
| **Persistence** | ✅ دارد (ذخیره در دیسک) | ❌ ندارد (در حافظه) |
| **Replication** | ✅ پشتیبانی می‌کند | ❌ پشتیبانی نمی‌کند |
| **Transactional** | ✅ دارد (atomic operations) | ❌ ندارد |
| **Pub/Sub** | ✅ دارد | ❌ ندارد |
| **Lua Scripting** | ✅ دارد | ❌ ندارد |
| **حافظه** | بیشتر (با روی‌ه) | کمتر (سبک‌تر) |
| **کاربرد** | کش، Queue، Session، Real-time | صرفاً Cache |

> **نکته کاربردی**: Redis برای پروژه‌های بزرگ و متنوع، Memcached برای کش ساده و سریع.

### ۵۴. Cache-aside Pattern چیست؟

**مفهوم**: الگوی مدیریت کش که در آن برنامه ابتدا از کش می‌خواند و در صورت عدم وجود، از دیتابیس.

**نحوه کار**:
```
1. درخواست داده → برنامه
2. بررسی کش (Cache Check)
3a. اگر موجود بود → برگردان
3b. اگر نبود → از دیتابیس بخوان
4. داده را در کش ذخیره کن
5. به کاربر برگردان
```

**مزایا**:
- فقط داده‌های درخواستی در کش قرار می‌گیرند
- ساده‌ترین و رایج‌ترین الگو
- مناسب برای داده‌هایی که کمتر تغییر می‌کنند

**معایب**:
- Stale Data (داده تاریخ گذشته) ممکن است
- برای داده‌های پربازدید کارایی خوبی دارد

> **نکته کاربردی**: در Laravel با `Cache::remember()` پیاده‌سازی می‌شود.

### ۵۵. تفاوت Write-through و Write-behind Cache چیست؟

**مفهوم**: دو استراتژی برای نوشتن در کش و دیتابیس.

**Write-through**:
- نوشتن همزمان در کش و دیتابیس
- داده‌ها **همیشه** یکسان هستند
- معایب: کندتر (چون دو عملیات)، احتمال خطا در یکی
- کاربرد: داده‌های حیاتی که باید دقیق باشند

```
بروزرسانی → کش (بلافاصله) → دیتابیس (بلافاصله)
```

**Write-behind**:
- نوشتن ابتدا در کش، سپس به‌طور **غیرهمزمان** در دیتابیس
- مزیت: سریع‌تر (چون کش پاسخ می‌دهد)
- معایب: احتمال از دست رفتن داده (اگر کش fail کند)
- کاربرد: سیستم‌هایی که سرعت برایشان مهم است

```
بروزرسانی → کش (بلافاصله) → [صف] → دیتابیس (بعداً)
```

> **نکته کاربردی**: Write-behind با Queue پیاده‌سازی می‌شود. Write-through ساده‌تر است.

### ۵۶. Cache Invalidation چیست و چه چالش‌هایی دارد؟

**مفهوم**: فرایند پاک کردن یا به‌روزرسانی کش وقتی داده‌ها تغییر می‌کنند.

**چالش‌ها**:
1. **زمان**: کی کش را پاک کنیم؟ بلافاصله یا با تاخیر؟
2. **هماهنگی**: اطمینان از هماهنگی همه کش‌ها (در چند سرور)
3. **شناسایی**: کدام کلیدها باید پاک شوند؟
4. **Stale Data**: داده تاریخ‌گذشته ممکن است برگردانده شود
5. **Cache Stampede**: چندین درخواست همزمان وقتی کش خالی می‌شود

**راه‌حل‌ها**:
1. **Time-based**: با TTL خودکار پاک می‌شود
2. **Event-based**: با رویدادهای تغییر داده پاک می‌شود
3. **Versioned Keys**: با تغییر نسخه، کلید جدید می‌سازیم
4. **Cache Tag**: دسته‌بندی و پاک کردن گروهی

> **نکته کاربردی**: در لاراول از `Cache::forget()` و `Cache::tags()` برای Cache Invalidation استفاده کنید.

### ۵۷. TTL چیست و چطور تنظیم می‌شود؟

**مفهوم**: Time-To-Live - زمان اعتبار کش.

**تنظیم در Laravel**:
```php
// با ثانیه
Cache::put('key', $value, 60); // 60 ثانیه

// با Carbon
Cache::put('key', $value, now()->addMinutes(10));

// با forever (تا زمان پاک کردن)
Cache::forever('key', $value);

// برای storeهای مختلف
Cache::store('redis')->put('key', $value, 300);
```

**توصیه‌ها**:
- داده‌های پویا: TTL کوتاه (۵-۱۰ دقیقه)
- داده‌های ثابت: TTL طولانی (۱-۲۴ ساعت)
- داده‌های حیاتی: از Event-based Invalidation استفاده کنید
- اگر مطمئن نیستید، TTL 5-10 دقیقه شروع کنید و تنظیم کنید

> **نکته کاربردی**: TTL متعادل انتخاب کنید تا هم کش به‌روز باشد و هم سرعت بالا بماند.

### ۵۸. چطور در Laravel از Redis برای Cache استفاده می‌کنید؟

**مراحل**:
1. **نصب**:
```bash
composer require predis/predis
```

2. **تنظیم .env**:
```env
REDIS_HOST=127.0.0.1
REDIS_PASSWORD=null
REDIS_PORT=6379
CACHE_DRIVER=redis
```

3. **تنظیم config/cache.php**:
```php
'redis' => [
    'driver' => 'redis',
    'connection' => 'default',
],
```

4. **استفاده**:
```php
use Illuminate\Support\Facades\Cache;

// ذخیره
Cache::store('redis')->put('user:1', $user, 600);

// بازیابی
$user = Cache::store('redis')->get('user:1');

// حذف
Cache::store('redis')->forget('user:1');

// Remember
$users = Cache::store('redis')->remember('all_users', 300, function() {
    return User::all();
});
```

> **نکته کاربردی**: از `Cache::remember()` برای Cache-aside Pattern استفاده کنید.

### ۵۹. Redis برای Queue و Session چطور استفاده می‌شود؟

**Queue با Redis**:
```env
QUEUE_CONNECTION=redis
```
```php
// در config/queue.php
'redis' => [
    'driver' => 'redis',
    'connection' => 'default',
    'queue' => 'default',
    'retry_after' => 90,
],
```
- مزیت: سریع، پایدار، پشتیبانی از delayed jobs
- کاربرد: صف‌های با حجم بالا

**Session با Redis**:
```env
SESSION_DRIVER=redis
```
```php
// در config/session.php
'redis' => [
    'driver' => 'redis',
    'connection' => 'default',
],
```
- مزیت: sessionهای مشترک بین چند سرور
- کاربرد: برنامه‌های مقیاس‌پذیر با load balancer

**مزیت اصلی**: Redis می‌تواند همزمان برای Cache، Queue و Session استفاده شود.

> **نکته کاربردی**: برای برنامه‌های توزیع‌شده، از Redis برای Session استفاده کنید.

### ۶۰. Stale Cache چیست و چطور جلوی آن را می‌گیرید؟

**مفهوم**: داده‌ای در کش که با داده اصلی دیتابیس **هماهنگ نیست** (تاریخ گذشته).

**علت**: داده در دیتابیس تغییر کرده ولی کش هنوز به‌روز نشده.

**راه‌حل‌ها**:

1. **TTL کوتاه**: خودکار پاک می‌شود (اما باعث cache miss بیشتر می‌شود)
2. **Event-driven Invalidation**: با تغییر داده، کش پاک می‌شود
```php
// در Model Event
static::updated(function ($user) {
    Cache::forget('user_' . $user->id);
});
```

3. **Cache Versioning**: نسخه‌ها را تغییر دهید
```php
$version = Cache::get('user_version', 1);
$key = "users_v{$version}";
```

4. **Refresh-ahead**: قبل از انقضا، کش را به‌روز کنید
5. **Write-through**: هم‌زمان با دیتابیس

**Prevention**:
- از TTL مناسب استفاده کنید
- برای تغییرات مهم، کش را بلافاصله پاک کنید
- از Cache Stampede prevention استفاده کنید

> **نکته کاربردی**: هیچ راه‌حل کامل وجود ندارد. از ترکیب TTL + Event-driven استفاده کنید.

### ۶۱. تفاوت ساختارهای داده‌ای Redis (String, List, Hash, Set) چیست؟

**مفهوم**: Redis از انواع داده‌های مختلف پشتیبانی می‌کند.

| نوع | توضیح | مثال | کاربرد |
|-----|-------|------|--------|
| **String** | ساده‌ترین، متن یا عدد | `"Hello"` | Cache ساده، شمارنده |
| **List** | لیست مرتب از رشته‌ها (آرایه) | `["a","b","c"]` | Queue، پیام‌ها |
| **Hash** | شبیه شیء (فیلد-مقدار) | `{name:"John", age:30}` | ذخیره اشیاء (مثل User) |
| **Set** | مجموعه غیرتکراری | `{"a","b","c"}` | Tagها، دسته‌بندی |
| **Sorted Set** | مجموعه مرتب با score | `{"a":1,"b":2,"c":3}` | رتبه‌بندی، زمان‌بندی |
| **Bitmaps** | عملیات بیتی | - | آمار (کاربران فعال) |
| **HyperLogLog** | تعداد اعضای منحصر‌به‌فرد | - | تعداد بازدیدکنندگان |
| **Geospatial** | موقعیت جغرافیایی | - | مکان‌یابی |

**انتخاب**:
- **String**: داده‌های ساده (User ID, Token)
- **Hash**: اشیاء با چند فیلد (User Profile)
- **List**: Queueها و Stackها
- **Set**: لیست‌های غیرتکراری (Tags)
- **Sorted Set**: رتبه‌بندی و Leaderboard

> **نکته کاربردی**: نوع داده مناسب را انتخاب کنید تا از امکانات Redis بهره ببرید.

## 🟨 بخش ۷: JavaScript

### ۶۲. تفاوت var، let و const چیست؟

**مفهوم**: سه روش برای تعریف متغیرها با رفتارهای متفاوت.

| ویژگی | var | let | const |
|-------|-----|-----|-------|
| **Scope** | تابعی (Function) | بلوکی (Block) | بلوکی (Block) |
| **Hoisting** | ✅ (با undefined) | ✅ (بدون مقداردهی) | ✅ (بدون مقداردهی) |
| **Re-declare** | ✅ مجاز | ❌ غیرمجاز | ❌ غیرمجاز |
| **Re-assign** | ✅ مجاز | ✅ مجاز | ❌ غیرمجاز |
| **Temporal Dead Zone** | ❌ | ✅ | ✅ |

**مثال**:
```javascript
// var - تابعی
function test() {
    if (true) {
        var x = 10;  // در کل تابع در دسترس است
    }
    console.log(x); // 10
}

// let - بلوکی
if (true) {
    let y = 20;  // فقط در این بلوک
}
console.log(y); // ReferenceError

// const - غیرقابل تغییر
const z = 30;
z = 40; // TypeError
```

> **نکته کاربردی**: همیشه از `const` استفاده کنید مگر زمانی که نیاز به تغییر داشته باشید، سپس از `let`. `var` را فراموش کنید.

### ۶۳. Closure چیست؟

**مفهوم**: تابعی که به متغیرهای محدوده بیرونی خود دسترسی دارد، حتی بعد از اتمام اجرای تابع بیرونی.

```javascript
function outer() {
    let message = "Hello";
    
    function inner() {
        console.log(message);  // دسترسی به متغیر بیرونی
    }
    
    return inner;
}

const fn = outer();
fn(); // "Hello" - حتی بعد از اتمام outer
```

**کاربردها**:
1. **Private variables**: شبیه‌سازی خصوصی‌سازی در OOP
2. **Function factories**: ساخت توابع پویا
3. **Event handlers**: دسترسی به داده‌های زمان تعریف
4. **Debouncing/Throttling**: کنترل فراخوانی‌ها

**مزیت**: encapsulation و داده‌های خصوصی در JavaScript

> **نکته کاربردی**: Closures در React Hooks و Event Handlers بسیار استفاده می‌شوند.

### ۶۴. Event Loop چطور کار می‌کند؟

**مفهوم**: مکانیزمی که JavaScript را قادر به اجرای عملیات غیرهمزمان (non-blocking) می‌کند.

**اجزای اصلی**:
1. **Call Stack**: لیست توابع در حال اجرا (LIFO)
2. **Web APIs**: setTimeout, DOM events, AJAX (مرورگر)
3. **Callback Queue (Task Queue)**: صف توابع آماده اجرا
4. **Event Loop**: حلقه‌ای که Callback Queue را به Call Stack منتقل می‌کند

**روند کار**:
```
1. کد همزمان → Call Stack
2. Web API (setTimeout) → ثبت و ادامه
3. بعد از زمان → Callback به Queue اضافه می‌شود
4. Event Loop: اگر Stack خالی باشد → Queue را به Stack منتقل می‌کند
5. Callback اجرا می‌شود
```

**Microtask vs Macrotask**:
- **Microtasks**: Promises, MutationObserver (اولویت بیشتر)
- **Macrotasks**: setTimeout, setInterval, I/O (اولویت کمتر)

> **نکته کاربردی**: Event Loop باعث می‌شود JavaScript با وجود تک‌رشته‌ای، غیرمسدود عمل کند.

### ۶۵. تفاوت Promise و Callback و async/await چیست؟

**مفهوم**: سه روش برای مدیریت عملیات غیرهمزمان.

**Callback**:
- قدیمی‌ترین روش
- مشکل: **Callback Hell** (هرم جهنم)
```javascript
getUser(1, (user) => {
    getPosts(user.id, (posts) => {
        getComments(posts[0].id, (comments) => {
            console.log(comments);
        });
    });
});
```

**Promise**:
- شیء برای عملیات آینده
- زنجیره‌ای با `.then().catch()`
```javascript
getUser(1)
    .then(user => getPosts(user.id))
    .then(posts => getComments(posts[0].id))
    .then(comments => console.log(comments))
    .catch(error => console.error(error));
```

**async/await**:
- کد همزمان‌گونه (synchronous-looking)
- با `try/catch` برای خطاها
```javascript
async function getData() {
    try {
        const user = await getUser(1);
        const posts = await getPosts(user.id);
        const comments = await getComments(posts[0].id);
        console.log(comments);
    } catch (error) {
        console.error(error);
    }
}
```

> **نکته کاربردی**: امروزه از async/await استفاده کنید، Promise را بشناسید، Callback را به عنوان تاریخچه بدانید.

### ۶۶. تفاوت == و === چیست؟

**مفهوم**: دو روش مقایسه با سطوح مختلف دقت.

**== (Loose Equality)**:
- بعد از **Type Coercion** (تبدیل نوع خودکار) مقایسه می‌کند
- می‌تواند نتایج غیرمنتظره داشته باشد
```javascript
5 == '5'     // true (تبدیل به عدد)
0 == false   // true (تبدیل به boolean)
null == undefined // true
```

**=== (Strict Equality)**:
- بدون تبدیل نوع مقایسه می‌کند
- دقیق‌تر و قابل پیش‌بینی‌تر
```javascript
5 === '5'    // false
0 === false  // false
null === undefined // false
```

**قوانین Type Coercion**:
- `null == undefined` فقط یک استثنا
- برای اشیاء: مقایسه مرجع (reference)

> **نکته کاربردی**: همیشه از `===` استفاده کنید، به‌جز موارد خاص مثل `x == null` (چک کردن null و undefined با هم).

### ۶۷. Hoisting چیست؟

**مفهوم**: بالا بردن تعاریف (declarations) به بالای محدوده در زمان کامپایل.

**انواع**:
1. **var declarations**: به بالا می‌روند و با `undefined` مقداردهی می‌شوند
```javascript
console.log(x); // undefined (خطا نمی‌دهد)
var x = 5;
// معادل: var x; console.log(x); x = 5;
```

2. **Function declarations**: به بالا می‌روند و کامل مقداردهی می‌شوند
```javascript
sayHello(); // "Hello" (کار می‌کند)
function sayHello() { console.log("Hello"); }
```

3. **let/const declarations**: به بالا می‌روند اما **مقداردهی نمی‌شوند** (Temporal Dead Zone)
```javascript
console.log(y); // ReferenceError (TDZ)
let y = 10;
```

**Temporal Dead Zone (TDZ)**:
- از ابتدای بلوک تا خط declaration
- دسترسی به متغیر در TDZ باعث ReferenceError می‌شود

> **نکته کاربردی**: برای خوانایی، همیشه متغیرها را در بالای scope تعریف کنید.

### ۶۸. تفاوت Arrow Function و Function معمولی در رفتار this چیست؟

**مفهوم**: این دو نوع تابع `this` را به طور متفاوت مدیریت می‌کنند.

**Function معمولی**:
- `this` بر اساس **context** زمان اجرا مشخص می‌شود
- در Event handler: `this` به عنصر اشاره می‌کند
```javascript
const obj = {
    name: 'John',
    greet: function() {
        console.log(this.name); // 'John'
    }
};
```

**Arrow Function**:
- `this` از **محیط خارجی** (lexical scope) گرفته می‌شود
- `this` ثابت و غیرقابل تغییر است
```javascript
const obj = {
    name: 'John',
    greet: () => {
        console.log(this.name); // undefined (this از بیرون)
    }
};
```

**کاربرد**:
- Arrow: برای Callbackها و زمانی که `this` خارجی را می‌خواهید
- Regular: برای متدهای شیء و زمانی که `this` به خود شیء نیاز دارید

> **نکته کاربردی**: از Arrow Function در Event Handlers و Promises استفاده کنید. در متدهای کلاس از Regular Function استفاده کنید.

### ۶۹. تفاوت Synchronous و Asynchronous چیست؟

**مفهوم**: دو روش اجرای کد با رفتارهای متفاوت.

**Synchronous (همزمان)**:
- کدها به **ترتیب** اجرا می‌شوند
- هر عملیات تا پایان اجرا، **مسدود** می‌کند (blocking)
```javascript
console.log('Start');
setTimeout(() => console.log('Timeout'), 0); // اینجا مشکل دارد
console.log('End');
// خروجی: Start, End, Timeout (اگر setTimeout باشد)
```

**Asynchronous (غیرهمزمان)**:
- کدها بدون مسدود کردن اجرا می‌شوند
- عملیات‌های سنگین به Queue می‌روند
```javascript
console.log('Start');
setTimeout(() => console.log('Timeout'), 1000);
console.log('End');
// خروجی: Start, End, Timeout (بعد از 1 ثانیه)
```

**مثال‌ها**:
- **Synchronous**: Math operations, string manipulations
- **Asynchronous**: HTTP requests, file I/O, timers, database queries

> **نکته کاربردی**: همیشه از Async/Await برای عملیات‌های غیرهمزمان استفاده کنید تا کد خوانا بماند.

### ۷۰. Event Bubbling و Event Delegation چیستند؟

**مفهوم**: دو مفهوم برای مدیریت رویدادها در DOM.

**Event Bubbling**:
- رویداد از **عنصر هدف** به سمت **بالا** (والدین) حرکت می‌کند
- ابتدا روی `div` سپس `body` سپس `document` اجرا می‌شود
```html
<div id="parent">
    <button id="child">Click</button>
</div>
```
```javascript
document.getElementById('parent').addEventListener('click', () => {
    console.log('Parent clicked!'); // بعد از Child اجرا می‌شود
});
```

**Event Delegation**:
- استفاده از Bubbling برای مدیریت رویدادهای **چندین عنصر** در یک عنصر والد
```javascript
// به جای چندین EventListener
document.querySelector('ul').addEventListener('click', (e) => {
    if (e.target.tagName === 'LI') {
        console.log('Item clicked:', e.target.textContent);
    }
});
```

**مزایای Event Delegation**:
1. عملکرد بهتر (یک Listener به جای N Listener)
2. مدیریت عناصر پویا (که بعداً اضافه می‌شوند)
3. کد تمیزتر

> **نکته کاربردی**: برای لیست‌ها و جدول‌ها از Event Delegation استفاده کنید.

## 🐘 بخش ۸: PHP

### ۷۱. تفاوت Interface و Abstract Class چیست؟

**مفهوم**: دو روش برای تعریف قراردادهای (contracts) در OOP.

| ویژگی | Interface | Abstract Class |
|-------|-----------|----------------|
| **پیاده‌سازی متد** | ❌ فقط امضا (signature) | ✅ می‌تواند پیاده‌سازی داشته باشد |
| **ارث‌بری** | چندین Interface (implements) | یک کلاس (extends) |
| **ویژگی‌ها (Properties)** | ❌ فقط constant | ✅ می‌تواند ویژگی داشته باشد |
| **Constructor** | ❌ ندارد | ✅ دارد |
| **Visibility** | همه public | public, protected, private |
| **کاربرد** | قرارداد و توانایی (what) | ساختار مشترک (how) |

**مثال**:
```php
// Interface: قرارداد
interface PaymentGateway {
    public function charge($amount);
}

// Abstract Class: ساختار مشترک
abstract class BaseController {
    protected function validate($data) { /* ... */ }
    abstract public function handle();
}
```

> **نکته کاربردی**: از Interface برای تعریف قابلیت‌ها، از Abstract برای اشتراک کد بین کلاس‌ها استفاده کنید.

### ۷۲. Trait چیست و چه مشکلی را حل می‌کند؟

**مفهوم**: گروهی از متدها که می‌توانند در چندین کلاس استفاده شوند (کد اشتراکی).

**مشکل**: PHP از **ارث‌بری چندگانه** پشتیبانی نمی‌کند. Trait این محدودیت را حل می‌کند.

**مثال**:
```php
trait Logger {
    public function log($message) {
        echo date('Y-m-d H:i:s') . ': ' . $message;
    }
}

trait Notifiable {
    public function notify($message) {
        $this->log($message); // متد از Trait دیگر
    }
}

class User {
    use Logger, Notifiable; // چندین Trait
}

$user = new User();
$user->log('Hello'); // 2024-01-01 12:00:00: Hello
```

**نکات**:
- Trait نمی‌تواند instance داشته باشد
- می‌تواند متدهای abstract داشته باشد
- اگر دو Trait متد همنام داشته باشند، با `insteadof` حل می‌شود

> **نکته کاربردی**: از Trait برای قابلیت‌های جانبی (Logging, Authorization) استفاده کنید.

### ۷۳. Magic Methods را نام ببرید

**مفهوم**: متدهای ویژه‌ای که در زمان‌های خاص به‌طور خودکار فراخوانی می‌شوند.

**لیست کامل**:
- `__construct()`: زمان ساخت شیء
- `__destruct()`: زمان نابودی شیء
- `__call($name, $args)`: فراخوانی متد غیرقابل دسترس
- `__callStatic($name, $args)`: فراخوانی متد استاتیک غیرقابل دسترس
- `__get($name)`: خواندن ویژگی غیرقابل دسترس
- `__set($name, $value)`: نوشتن ویژگی غیرقابل دسترس
- `__isset($name)`: چک کردن وجود ویژگی غیرقابل دسترس
- `__unset($name)`: حذف ویژگی غیرقابل دسترس
- `__sleep()`: قبل از serialize
- `__wakeup()`: بعد از unserialize
- `__toString()`: تبدیل به رشته (مثل echo)
- `__invoke()`: وقتی شیء به عنوان تابع فراخوانی شود
- `__clone()`: بعد از clone
- `__debugInfo()`: برای var_dump

**مثال**:
```php
class User {
    private $data = [];
    
    public function __get($name) {
        return $this->data[$name] ?? null;
    }
    
    public function __set($name, $value) {
        $this->data[$name] = $value;
    }
    
    public function __toString() {
        return $this->data['name'] ?? 'Unknown';
    }
}
```

> **نکته کاربردی**: `__get` و `__set` برای Dynamic Properties و `__toString` برای نمایش شیء.

### ۷۴. تفاوت include و require چیست؟

**مفهوم**: دو روش برای شامل کردن فایل‌ها.

| ویژگی | include | require |
|-------|---------|---------|
| **خطای فایل نبودن** | Warning (اجرا ادامه می‌یابد) | Fatal Error (اجرا متوقف می‌شود) |
| **توقف اجرا** | ❌ | ✅ |
| **خطای نهایی** | E_WARNING | E_COMPILE_ERROR |
| **زمان** | زمان اجرا | زمان اجرا |

**انواع دیگر**:
- `include_once`: فقط یک بار include کند
- `require_once`: فقط یک بار require کند

**کاربرد**:
- **require**: برای فایل‌های حیاتی (config, functions)
- **include**: برای فایل‌های غیرحیاتی (templates, ads)
- **require_once**: برای کلاس‌ها و کتابخانه‌ها

```php
// حیاتی
require_once 'config/database.php';

// غیرحیاتی
include 'templates/header.php';
```

> **نکته کاربردی**: برای کلاس‌ها و وابستگی‌ها از `require_once` استفاده کنید. برای templates از `include`.

### ۷۵. PSR-4 و PSR-12 چیستند؟

**مفهوم**: استانداردهای رسمی PHP-FIG برای کدنویسی.

**PSR-4 (Autoloading)**:
- استاندارد **Auto-loading** کلاس‌ها
- نام‌های فضایی (namespace) به مسیر فایل‌ها نگاشت می‌شوند
```php
// namespace App\Models\User → app/Models/User.php
// namespace App\Services\Payment → app/Services/Payment.php
```

**PSR-12 (Coding Style)**:
- استاندارد **کدنویسی** (جایگزین PSR-2)
- قوانین:
  - Indentation: 4 spaces
  - Opening braces: در خط بعد
  - Namespace: یک خط خالی بعد از آن
  - use: یک خط خالی بعد از آن
  - کلاس‌ها: یک خط خالی بین متدها
  - کنترل‌ساختارها: فضای خالی بعد از if/for/while

**سایر PSRها**:
- PSR-1: Basic Coding Standard
- PSR-3: Logger Interface
- PSR-7: HTTP Message Interface
- PSR-11: Container Interface

> **نکته کاربردی**: از PHP_CodeSniffer برای بررسی خودکار PSR-12 استفاده کنید.

### ۷۶. تفاوت متد و پراپرتی Static و Instance چیست؟

**مفهوم**: دو نوع مختلف برای دسترسی به متدها و ویژگی‌ها.

| ویژگی | Static | Instance |
|-------|--------|----------|
| **نحوه دسترسی** | `ClassName::$prop` یا `self::$prop` | `$obj->prop` |
| **نیاز به نمونه** | ❌ خیر | ✅ بله (new ClassName()) |
| **حافظه** | یک نسخه برای کل کلاس | یک نسخه برای هر شیء |
| **دسترسی به `$this`** | ❌ غیرقابل دسترس | ✅ قابل دسترس |
| **زمان** | زمان بارگذاری کلاس | زمان نمونه‌سازی |

**مثال**:
```php
class Counter {
    public static $count = 0;  // استاتیک
    
    public function __construct() {
        self::$count++;  // همه نمونه‌ها با هم
    }
    
    public static function getCount() {
        return self::$count;
    }
}

$c1 = new Counter();
$c2 = new Counter();
echo Counter::$count; // 2
```

> **نکته کاربردی**: از Static برای داده‌های مشترک و ابزارها (Utilities) استفاده کنید.

### ۷۷. Null Coalescing Operator (??) و Nullsafe Operator (?->) چه کاربردی دارند؟

**مفهوم**: دو عملگر PHP 7 و PHP 8 برای مدیریت null.

**?? (Null Coalescing)**:
- مقدار پیش‌فرض اگر متغیر null باشد
- معادل `isset($x) ? $x : $default`
```php
$name = $user->name ?? 'Guest';
// اگر $user->name null یا undefined باشد → 'Guest'

$age = $user->age ?? $user->birth_year ?? 18;
// چندین سطح
```

**?-> (Nullsafe Operator)**:
- دسترسی به متد/ویژگی فقط اگر شیء null نباشد
- در PHP 8 اضافه شده
```php
// بدون Nullsafe
$city = $user->address ? $user->address->city : null;

// با Nullsafe
$city = $user->address?->city?->name ?? 'Unknown';
```

**تفاوت**:
- `??`: برای متغیرها و کلیدهای آرایه
- `?->`: برای فراخوانی زنجیره‌ای روی اشیاء

> **نکته کاربردی**: `??` و `?->` کد را تمیزتر و امن‌تر از `isset()` می‌کنند.

### ۷۸. تفاوت Pass by Value و Pass by Reference چیست؟

**مفهوم**: دو روش برای ارسال آرگومان به تابع.

**Pass by Value (پیش‌فرض)**:
- **کپی** از مقدار ارسال می‌شود
- تغییر در تابع تأثیری روی متغیر اصلی ندارد
```php
function increment($num) {
    $num++;
}
$value = 10;
increment($value);
echo $value; // 10 (تغییری نکرد)
```

**Pass by Reference**:
- با `&` مشخص می‌شود
- **اشاره‌گر** به متغیر اصلی ارسال می‌شود
- تغییر در تابع روی متغیر اصلی تأثیر می‌گذارد
```php
function increment(&$num) {
    $num++;
}
$value = 10;
increment($value);
echo $value; // 11 (تغییر کرد)
```

**کاربرد Reference**:
- تغییر آرایه‌های بزرگ (صرفه‌جویی در حافظه)
- Return کردن چندین مقدار
- Sorting functions

> **نکته کاربردی**: فقط در صورت نیاز از Reference استفاده کنید (کد را گیج‌کننده می‌کند).

### ۷۹. Namespace چیست و چه مشکلی را حل می‌کند؟

**مفهوم**: مکانیزمی برای سازماندهی کد و جلوگیری از تداخل نام‌ها.

**مشکل**: بدون Namespace، دو کلاس با نام یکسان تداخل می‌کنند.
```php
// file1.php
class User { /* ... */ }

// file2.php
class User { /* ... */ } // Fatal error: cannot redeclare
```

**Namespace**:
```php
// file1.php
namespace App\Models;
class User { /* ... */ }

// file2.php
namespace App\Services;
class User { /* ... */ }

// استفاده
$user1 = new App\Models\User();
$user2 = new App\Services\User();
```

**قوانین**:
- **Import**: با `use`
```php
use App\Models\User;
use App\Services\User as ServiceUser;
```

**PSR-4**: Namespace باید با مسیر فایل مطابق باشد
- `App\Models\User` → `app/Models/User.php`

> **نکته کاربردی**: Namespace ضروری برای پروژه‌های بزرگ و استفاده از کامپوزر است.

### ۸۰. تفاوت == و === در PHP چیست؟ (Type Juggling)

**مفهوم**: دو عملگر مقایسه با رفتارهای متفاوت.

**== (Loose Comparison)**:
- بعد از **Type Juggling** (تبدیل نوع خودکار) مقایسه می‌کند
- می‌تواند نتایج غیرمنتظره داشته باشد
```php
0 == false   // true (0 == 0)
"1" == 1     // true ("1" → 1)
"" == 0      // true ("" → 0)
"abc" == 0   // true (آماده‌سازی به عدد → 0)
null == 0    // true
```

**=== (Strict Comparison)**:
- بدون تبدیل نوع مقایسه می‌کند
- دقیق و قابل پیش‌بینی
```php
0 === false   // false
"1" === 1     // false
null === 0    // false
```

**مقایسه‌های ویژه**:
- `null == null` → true
- `null === null` → true
- `[] == []` → true (آرایه‌ها به عنوان اشیاء)
- `[] === []` → true

> **نکته کاربردی**: همیشه از `===` استفاده کنید، به‌جز موارد خاص مثل `is_null($x) || $x === false`.

## 🌐 بخش ۹: RESTful API

### ۸۱. تفاوت PUT و PATCH چیست؟

**مفهوم**: دو متد HTTP برای بروزرسانی منابع.

**PUT**:
- **جایگزینی کامل** منبع
- کل منبع را با داده جدید جایگزین می‌کند
- فیلدهای از قلم افتاده حذف می‌شوند یا به default برمی‌گردند
- Idempotent (چندباره انجام شود، نتیجه یکسان)
```http
PUT /users/1
{"name": "John", "age": 30, "email": "john@test.com"}
```

**PATCH**:
- **بروزرسانی جزئی** منبع
- فقط فیلدهای ارسالی را تغییر می‌دهد
- فیلدهای دیگر دست نخورده می‌مانند
- می‌تواند Idempotent باشد یا نباشد
```http
PATCH /users/1
{"age": 31}
// فقط age تغییر می‌کند
```

> **نکته کاربردی**: برای بروزرسانی کامل از PUT و برای بروزرسانی جزئی از PATCH استفاده کنید.

### ۸۲. تفاوت POST و PUT چیست؟

**مفهوم**: دو متد HTTP با اهداف متفاوت.

| ویژگی | POST | PUT |
|-------|------|-----|
| **هدف** | ایجاد منبع جدید | بروزرسانی کامل منبع |
| **Idempotency** | ❌ نه (غیر Idempotent) | ✅ بله (Idempotent) |
| **تأثیر** | ایجاد می‌کند | جایگزین می‌کند |
| **URI** | URL جمع (collection) | URL خاص (item) |
| **مثال** | `POST /users` | `PUT /users/1` |

**Idempotency**:
- POST: دو بار درخواست → دو منبع جدید
- PUT: دو بار درخواست → همان منبع

**کاربرد**:
- **POST**: ایجاد کاربر جدید، ارسال فرم
- **PUT**: بروزرسانی کامل مشخصات کاربر

> **نکته کاربردی**: از POST برای ایجاد و از PUT برای بروزرسانی کامل استفاده کنید.

### ۸۳. Idempotency در API چیست؟

**مفهوم**: ویژگی درخواست که چندباره انجام شود، نتیجه یکسانی دارد و هیچ عارضه جانبی جدیدی ایجاد نمی‌کند.

**متدهای Idempotent**:
- ✅ GET, HEAD, OPTIONS, TRACE: همیشه Idempotent
- ✅ PUT, DELETE: Idempotent (با فرض اجرای صحیح)
- ❌ POST: Idempotent نیست
- ❌ PATCH: معمولاً Idempotent نیست

**مثال**:
```http
DELETE /users/1  (چندباره → همان نتیجه: کاربر حذف شده)

PUT /users/1     (چندباره → همان نتیجه: کاربر همان است)

POST /users      (چندباره → نتیجه متفاوت: کاربران جدید)
```

**مهم**: حتی DELETE به معنای واقعی Idempotent است (بعد از حذف، دیگر حذف نمی‌شود).

> **نکته کاربردی**: برای اطمینان، از توکن‌های یکتای درخواست (Idempotency Key) استفاده کنید.

### ۸۴. کدهای وضعیت HTTP مهم را توضیح دهید

**مفهوم**: کدهایی که نتیجه درخواست HTTP را نشان می‌دهند.

**2xx - Success**:
- **200 OK**: درخواست موفق (GET, PUT, DELETE)
- **201 Created**: منبع جدید ایجاد شد (POST)
- **202 Accepted**: درخواست پذیرفته شد (پردازش ناهمگام)
- **204 No Content**: موفق اما بدون محتوا (DELETE)

**4xx - Client Error**:
- **400 Bad Request**: درخواست نامعتبر (validation)
- **401 Unauthorized**: احراز هویت نیاز است
- **403 Forbidden**: دسترسی ممنوع (مجوز ندارد)
- **404 Not Found**: منبع پیدا نشد
- **409 Conflict**: تداخل (مثل دوبل بودن)
- **422 Unprocessable Entity**: داده‌های ارسالی نامعتبر (validation)

**5xx - Server Error**:
- **500 Internal Server Error**: خطای سرور
- **502 Bad Gateway**: مشکل در gateway/proxy
- **503 Service Unavailable**: سرور در دسترس نیست
- **504 Gateway Timeout**: Timeout در gateway

> **نکته کاربردی**: همیشه کد وضعیت صحیح و پیام مناسب برگردانید.

### ۸۵. Statelessness در REST چه معنایی دارد؟

**مفهوم**: یکی از اصول معماری REST که سرور هیچ اطلاعاتی از وضعیت (state) کلاینت بین درخواست‌ها ذخیره نمی‌کند.

**ویژگی‌ها**:
1. هر درخواست مستقل است و شامل **همه** اطلاعات مورد نیاز است
2. سرور نیازی به Session/Cookie ندارد
3. مقیاس‌پذیری بالا (هر سرور می‌تواند پاسخ دهد)
4. ساده‌تر برای Cache کردن

**مثال**:
```http
// Session-based (Stateful)
GET /profile → Cookie: PHPSESSID=abc123

// RESTful (Stateless)
GET /profile → Authorization: Bearer token_xyz
```

**پیاده‌سازی**:
- از توکن‌های JWT یا API Keys استفاده کنید
- تمام داده‌ها را در خود درخواست بفرستید (نه در Session)

> **نکته کاربردی**: برای APIها همیشه از احراز هویت Stateless (Token) استفاده کنید.

### ۸۶. Versioning یک API چطور انجام می‌شود؟

**مفهوم**: مدیریت تغییرات API بدون شکستن کلاینت‌های موجود.

**روش‌های اصلی**:

1. **URL Versioning** (رایج‌ترین):
```
/v1/users
/v2/users
```

2. **Header Versioning**:
```
Accept: application/vnd.myapi.v1+json
Accept: application/vnd.myapi.v2+json
```

3. **Query Parameter**:
```
/users?version=1
/users?version=2
```

4. **Content Negotiation**:
```
Accept: application/json; version=1.0
```

**بهترین روش**: URL Versioning (ساده، خوانا، cache-friendly)

**استراتژی**:
- حفظ نسخه‌های قدیمی حداقل ۶ ماه
- اعمال تغییرات Breaking در نسخه جدید
- مستندسازی کامل تغییرات

> **نکته کاربردی**: از URL Versioning در Laravel با `Route::prefix('v1')->group()` استفاده کنید.

### ۸۷. تفاوت Query Parameter و Path Parameter چیست؟

**مفهوم**: دو روش برای ارسال داده در URL.

**Path Parameter (مشخص‌کننده)**:
- جزء **مسیر** (path) URL
- برای شناسایی **منبع خاص**
```
/users/123          ← 123 Path Parameter
/products/iphone-15 ← iphone-15 Path Parameter
```

**Query Parameter (فیلترکننده)**:
- بعد از `?` در URL
- برای **فیلتر کردن، مرتب‌سازی، صفحه‌بندی**
```
/users?page=2&limit=10&sort=name
/products?category=electronics&min_price=100
```

**مثال کامل**:
```
GET /users/123/posts?page=2&sort=created_at
     ↑پارامتر مسیر   ↑پارامترهای جستجو
```

> **نکته کاربردی**: از Path برای شناسه‌های منبع و از Query برای فیلترها و تنظیمات استفاده کنید.

### ۸۸. Rate Limiting در API چطور اجرا می‌شود؟

**مفهوم**: محدودیت تعداد درخواست‌ها برای جلوگیری از سوءاستفاده و حفظ عملکرد.

**پیاده‌سازی در Laravel**:
```php
// در Route
Route::middleware('throttle:60,1')->group(function() {
    // 60 درخواست در 1 دقیقه
});

// در کنترلر با ثانیه
Route::middleware('throttle:100:1')->get('/api/users', ...);
```

**پیکربندی**:
```php
// config/app.php
'throttle' => [
    'max_attempts' => 60,
    'decay_minutes' => 1,
],
```

**با Redis**:
```php
use Illuminate\Support\Facades\RateLimiter;

RateLimiter::for('api', function ($job) {
    return Limit::perMinute(100)->by($job->user->id);
});
```

**پیاده‌سازی دیگر**:
- **Nginx**: `limit_req_zone`
- **Redis**: با Increment و TTL
- **AWS API Gateway**: Built-in

**پاسخ**: `HTTP 429 Too Many Requests`

> **نکته کاربردی**: از Rate Limiting برای APIهای عمومی حتماً استفاده کنید.

### ۸۹. HATEOAS چیست؟

**مفهوم**: Hypermedia As The Engine Of Application State - اصل در REST که پاسخ API شامل لینک‌های اقدامات بعدی است.

**مثال**:
```json
{
    "user": {
        "id": 123,
        "name": "John Doe",
        "_links": {
            "self": { "href": "/users/123" },
            "update": { "href": "/users/123", "method": "PUT" },
            "delete": { "href": "/users/123", "method": "DELETE" },
            "posts": { "href": "/users/123/posts" }
        }
    }
}
```

**مزایا**:
1. **قابل کشف**: کلاینت می‌تواند قابلیت‌ها را بفهمد
2. **قابل تکامل**: سرور می‌تواند مسیرها را تغییر دهد (کلاینت از لینک‌ها استفاده می‌کند)
3. **خودمستند**: خود API مستند است

**چالش‌ها**:
- پیچیدگی بیشتر
- حجم پاسخ بیشتر
- نیاز به طراحی دقیق

> **نکته کاربردی**: در پروژه‌های بزرگ، HATEOAS برای کشف API مفید است. در پروژه‌های کوچک، ممکن است زیادی باشد.

## 🧱 بخش ۱۰: OOP

### ۹۰. چهار اصل OOP را نام ببرید

**مفهوم**: چهار اصل اساسی برنامه‌نویسی شی‌گرا.

**۱. Encapsulation (مخفی‌سازی)**:
- پنهان کردن داده‌های داخلی و ارائه interface برای دسترسی
- با visibility modifiers: `private`, `protected`, `public`
- مزیت: کنترل دسترسی، جلوگیری از تغییرات ناخواسته

**۲. Abstraction (انتزاع)**:
- نمایش interface ساده و مخفی کردن جزئیات پیاده‌سازی
- با Abstract Classes و Interfaces
- مزیت: تمرکز بر "چه کاری" نه "چگونه"

**۳. Inheritance (ارث‌بری)**:
- ایجاد کلاس‌های جدید بر اساس کلاس‌های موجود
- با `extends` در PHP
- مزیت: اشتراک کد، روابط is-a

**۴. Polymorphism (چندریختی)**:
- توانایی اشیاء مختلف برای پاسخ به یک interface یکسان
- Method Overriding (runtime) و Method Overloading (compile-time)
- مزیت: انعطاف‌پذیری، قابلیت توسعه

### ۹۱. Polymorphism چیست و چه انواعی دارد؟

**مفهوم**: توانایی یک اینترفیس برای رفتارهای مختلف در کلاس‌های مختلف.

**انواع**:

**۱. Runtime Polymorphism (Method Overriding)**:
- کلاس فرزند متد والد را بازنویسی می‌کند
- تصمیم‌گیری در زمان اجرا
```php
class Animal {
    public function speak() { echo "Animal speaks"; }
}
class Dog extends Animal {
    public function speak() { echo "Bark"; }
}
class Cat extends Animal {
    public function speak() { echo "Meow"; }
}

$animals = [new Dog(), new Cat()];
foreach ($animals as $animal) {
    $animal->speak(); // Bark, Meow
}
```

**۲. Compile-time Polymorphism (Method Overloading)**:
- متدهای همنام با پارامترهای مختلف
- در PHP با `__call()` شبیه‌سازی می‌شود
```php
class Calculator {
    public function add($a, $b = null) {
        if ($b === null) return $a;
        return $a + $b;
    }
}
```

> **نکته کاربردی**: Polymorphism کد را انعطاف‌پذیرتر و قابل توسعه‌تر می‌کند.

### ۹۲. Encapsulation چطور در PHP پیاده‌سازی می‌شود؟

**مفهوم**: با Visibility Modifiers (سطح دسترسی) کنترل می‌شود.

**سه سطح دسترسی**:

1. **`public`**: قابل دسترسی از هر جایی
```php
public $name;  // همه می‌توانند بخوانند/بنویسند
```

2. **`protected`**: قابل دسترسی در کلاس و فرزندان
```php
protected $email;  // فقط در کلاس و زیرکلاس‌ها
```

3. **`private`**: فقط در همان کلاس
```php
private $password;  // فقط در خود کلاس
```

**مثال عملی**:
```php
class User {
    private $password;  // مخفی
    protected $email;   // قابل دسترسی در فرزندان
    public $name;       // عمومی
    
    public function setPassword($pass) {
        $this->password = hash('sha256', $pass);
    }
    
    private function hashPassword($pass) {
        // فقط داخل کلاس
    }
}
```

**مزایا**:
- کنترل دسترسی دقیق به داده
- جلوگیری از تغییرات ناخواسته
- تست‌پذیری بهتر

> **نکته کاربردی**: از `private` برای داده‌های حساس و `protected` برای داده‌های قابل اشتراک استفاده کنید.

### ۹۳. تفاوت Composition و Inheritance چیست؟

**مفهوم**: دو روش برای استفاده مجدد از کد.

**Inheritance (ارث‌بری)**:
- رابطه **is-a** (است)
- کلاس فرزند از کلاس والد ارث می‌برد
```php
class Vehicle { /* ... */ }
class Car extends Vehicle { /* Car is-a Vehicle */ }
```

**Composition (ترکیب)**:
- رابطه **has-a** (دارد)
- کلاس شامل اشیاء دیگری است
```php
class Engine { /* ... */ }
class Wheels { /* ... */ }

class Car {
    private $engine;  // Car has-a Engine
    private $wheels;  // Car has-a Wheels
}
```

**مقایسه**:

| Inheritance | Composition |
|-------------|-------------|
| عمودی (vertical) | افقی (horizontal) |
| Tight coupling | Loose coupling |
| تغییر والد = تغییر فرزندان | تغییر جزئی = تغییر کمتر |
| محدود به یک والد (در PHP) | چندین شیء ممکن است |
| مناسب برای is-a | مناسب برای has-a |

**Favor Composition over Inheritance**:
- Composition انعطاف‌پذیرتر است
- Inheritance برای روابط واقعی is-a

> **نکته کاربردی**: از Inheritance برای روابط واقعی is-a (Animal → Dog) و از Composition برای قابلیت‌ها استفاده کنید.

### ۹۴. Abstraction چه تفاوتی با Encapsulation دارد؟

**مفهوم**: دو اصل مکمل اما متفاوت.

**Abstraction (انتزاع)**:
- **چه کاری** (what) را نشان می‌دهد، نه **چگونه** (how)
- تمرکز بر Interface
- با Abstract Classes و Interfaces پیاده‌سازی می‌شود
```php
interface PaymentGateway {
    public function charge($amount);  // فقط امضا
    // جزئیات پیاده‌سازی مشخص نیست
}
```

**Encapsulation (مخفی‌سازی)**:
- **چگونه** داده‌ها و رفتارها محافظت می‌شوند
- تمرکز بر کنترل دسترسی
- با `private`, `protected` پیاده‌سازی می‌شود

**تفاوت کلیدی**:
- Abstraction: **سطح بالا** (design level)
- Encapsulation: **سطح پایین** (implementation level)
- Abstraction: چه کاری باید انجام شود
- Encapsulation: چگونه داده‌ها محافظت شوند

**مثال**:
```php
// Abstraction: interface
interface Logger {
    public function log($message);
}

// Encapsulation: پیاده‌سازی با جزئیات مخفی
class FileLogger implements Logger {
    private $filePath;  // مخفی (Encapsulation)
    
    public function log($message) {
        // پیاده‌سازی مخفی (Abstraction + Encapsulation)
        file_put_contents($this->filePath, $message . PHP_EOL, FILE_APPEND);
    }
}
```

> **نکته کاربردی**: هر دو با هم برای طراحی تمیز و امن استفاده می‌شوند.

### ۹۵. Late Static Binding در PHP چیست؟

**مفهوم**: توانایی ارجاع به کلاسی که در زمان اجرا فراخوانی شده است، نه کلاسی که در آن تعریف شده است.

**مشکل**: با `self::` همیشه به کلاس فعلی ارجاع داده می‌شود.

```php
class ParentClass {
    public static function who() {
        echo self::class;  // همیشه ParentClass
    }
}

class ChildClass extends ParentClass {
    public static function who() {
        echo self::class;  // همیشه ChildClass
    }
}
```

**راه‌حل: Late Static Binding با `static::`**:
```php
class ParentClass {
    public static function who() {
        echo static::class;  // در زمان اجرا مشخص می‌شود
    }
}

class ChildClass extends ParentClass {
    // who() ارث‌بری می‌شود
}

ParentClass::who();  // ParentClass
ChildClass::who();   // ChildClass (Late Static Binding)
```

**مثال کاربردی**:
```php
class Model {
    protected static $table;
    
    public static function getTable() {
        return static::$table ?? 'default';
    }
}

class User extends Model {
    protected static $table = 'users';
}

echo User::getTable(); // 'users'
```

> **نکته کاربردی**: برای کلاس‌های پایه (base classes) که باید به کلاس فرزند ارجاع دهند از `static::` استفاده کنید.

## 📐 بخش ۱۱: SOLID

### ۹۶. اصل Single Responsibility چیست؟

**مفهوم**: هر کلاس باید **یک دلیل** برای تغییر داشته باشد (یک مسئولیت).

**مثال نقض**:
```php
class User {
    public function save() { /* ذخیره در دیتابیس */ }
    public function sendEmail() { /* ارسال ایمیل */ }
    public function generateReport() { /* گزارش‌گیری */ }
}
// سه مسئولیت مختلف → سه دلیل برای تغییر
```

**راه‌حل**:
```php
class User {
    // فقط مدیریت کاربر
}

class UserRepository {
    // فقط ذخیره‌سازی
}

class EmailService {
    // فقط ارسال ایمیل
}

class ReportGenerator {
    // فقط گزارش‌گیری
}
```

**مزایا**:
- کد قابل فهم‌تر
- تست‌پذیری بهتر
- تغییرات آسان‌تر (تأثیر کمتر)

> **نکته کاربردی**: اگر یک کلاس بیش از حد بزرگ شد، آن را به کلاس‌های کوچکتر بشکنید.

### ۹۷. اصل Open/Closed چیست؟

**مفهوم**: کلاس‌ها باید **برای توسعه باز** و **برای تغییر بسته** باشند.

**مثال نقض**:
```php
class Discount {
    public function calculate($user, $amount) {
        if ($user->type == 'student') return $amount * 0.9;
        if ($user->type == 'senior') return $amount * 0.85;
        if ($user->type == 'member') return $amount * 0.95;
        return $amount;
    }
}
// برای افزودن نوع جدید، کلاس را تغییر می‌دهیم → Open/Closed نقض
```

**راه‌حل**:
```php
interface DiscountStrategy {
    public function calculate($amount);
}

class StudentDiscount implements DiscountStrategy {
    public function calculate($amount) { return $amount * 0.9; }
}

class SeniorDiscount implements DiscountStrategy {
    public function calculate($amount) { return $amount * 0.85; }
}

// کلاس باز برای توسعه (می‌توانیم کلاس جدید اضافه کنیم)
class Discount {
    public function calculate($amount, DiscountStrategy $strategy) {
        return $strategy->calculate($amount);
    }
}
```

> **نکته کاربردی**: از Interface برای جداسازی رفتارها استفاده کنید.

### ۹۸. اصل Liskov Substitution چیست؟

**م概念**: اشیاء کلاس فرزند باید بتوانند جایگزین اشیاء کلاس والد شوند بدون تغییر رفتار برنامه.

**مثال نقض**:
```php
class Rectangle {
    protected $width, $height;
    public function setWidth($w) { $this->width = $w; }
    public function setHeight($h) { $this->height = $h; }
    public function area() { return $this->width * $this->height; }
}

class Square extends Rectangle {
    public function setWidth($w) {
        $this->width = $w;
        $this->height = $w; // نقض LSP!
    }
    public function setHeight($h) {
        $this->height = $h;
        $this->width = $h; // نقض LSP!
    }
}

function testArea(Rectangle $rect) {
    $rect->setWidth(5);
    $rect->setHeight(4);
    assert($rect->area() == 20); // در Square شکست می‌خورد!
}
```

**تشخیص**:
- آیا متدهای کلاس فرزند رفتار غیرمنتظره دارند؟
- آیا preconditionها قوی‌تر شده‌اند؟
- آیا postconditionها ضعیف‌تر شده‌اند؟

> **نکته کاربردی**: قبل از ارث‌بری، مطمئن شوید رابطه is-a واقعی وجود دارد.

### ۹۹. اصل Interface Segregation چیست؟

**مفهوم**: اینترفیس‌ها را **کوچک و اختصاصی** طراحی کنید نه بزرگ و عمومی.

**مثال نقض**:
```php
interface Worker {
    public function work();
    public function eat();
    public function sleep();
}

class Human implements Worker {
    public function work() { /* ... */ }
    public function eat() { /* ... */ }
    public function sleep() { /* ... */ }
}

class Robot implements Worker {
    public function work() { /* ... */ }
    public function eat() { /* 🚫 نمی‌خورد */ }
    public function sleep() { /* 🚫 نمی‌خوابد */ }
}
// Robot مجبور به پیاده‌سازی متدهای اضافی است
```

**راه‌حل**:
```php
interface Workable {
    public function work();
}

interface Eatable {
    public function eat();
}

interface Sleepable {
    public function sleep();
}

class Human implements Workable, Eatable, Sleepable {
    // فقط متدهای مورد نیاز
}

class Robot implements Workable {
    // فقط متدهای مورد نیاز
}
```

> **نکته کاربردی**: اینترفیس‌ها را بر اساس قابلیت‌ها طراحی کنید، نه موجودیت‌ها.

### ۱۰۰. اصل Dependency Inversion چیست؟

**مفهوم**: ماژول‌های سطح بالا نباید به ماژول‌های سطح پایین وابسته باشند؛ هر دو باید به **Abstraction** وابسته باشند.

**مثال نقض**:
```php
// وابستگی مستقیم به کلاس بتن
class EmailNotifier {
    public function send($message) { /* ... */ }
}

class UserService {
    private $notifier;
    
    public function __construct() {
        $this->notifier = new EmailNotifier(); // وابستگی سخت
    }
}
```

**راه‌حل**:
```php
// Abstraction
interface Notifier {
    public function send($message);
}

// پیاده‌سازی بتن
class EmailNotifier implements Notifier { /* ... */ }
class SmsNotifier implements Notifier { /* ... */ }

// وابستگی به Abstraction
class UserService {
    private $notifier;
    
    public function __construct(Notifier $notifier) { // تزریق وابستگی
        $this->notifier = $notifier;
    }
}
```

**مزایا**:
- تست‌پذیری آسان (mock)
- تغییر پیاده‌سازی بدون تغییر کلاس
- Loose coupling

> **نکته کاربردی**: همیشه به Interfaceها وابسته باشید، نه به پیاده‌سازی‌های بتن.

## 🎨 بخش ۱۲: Design Patterns

### ۱۰۱. Strategy Pattern چیست و چه زمانی استفاده می‌شود؟

**مفهوم**: الگوریتم‌های قابل تعویض با یک اینترفیس مشترک.

**ساختار**:
```
Context → Strategy (interface) → ConcreteStrategyA, ConcreteStrategyB
```

**مثال**:
```php
interface PaymentStrategy {
    public function pay($amount);
}

class ZarinpalPayment implements PaymentStrategy {
    public function pay($amount) { /* پرداخت با زرین‌پال */ }
}

class StripePayment implements PaymentStrategy {
    public function pay($amount) { /* پرداخت با استریپ */ }
}

class PaymentContext {
    private $strategy;
    
    public function setStrategy(PaymentStrategy $strategy) {
        $this->strategy = $strategy;
    }
    
    public function executePayment($amount) {
        $this->strategy->pay($amount);
    }
}
```

**زمان استفاده**:
- چندین روش برای انجام یک کار (مثل پرداخت، اعتبارسنجی، مرتب‌سازی)
- نیاز به تغییر رفتار در زمان اجرا
- جلوگیری از if-elseهای بزرگ

> **نکته کاربردی**: Strategy با Dependency Injection ترکیب بسیار خوبی دارد.

### ۱۰۲. Factory Pattern و Factory Method چه تفاوتی دارند؟

**مفهوم**: هر دو الگوهای ایجاد شیء با سطوح مختلف پیچیدگی.

**Factory (Simple Factory)**:
- یک کلاس جداگانه برای ساخت اشیاء
- متد `create()` که بسته به ورودی، شیء مناسب را برمی‌گرداند
```php
class PaymentFactory {
    public static function create($type) {
        return match($type) {
            'zarinpal' => new ZarinpalPayment(),
            'stripe' => new StripePayment(),
            default => new DefaultPayment(),
        };
    }
}
```

**Factory Method**:
- متدی در کلاس (معمولاً abstract) برای ساخت اشیاء
- کلاس‌های فرزند تصمیم می‌گیرند کدام شیء ساخته شود
```php
abstract class PaymentProcessor {
    abstract protected function createPayment($amount);
    
    public function process($amount) {
        $payment = $this->createPayment($amount);
        return $payment->pay();
    }
}

class ZarinpalProcessor extends PaymentProcessor {
    protected function createPayment($amount) {
        return new ZarinpalPayment($amount);
    }
}
```

**تفاوت**:
- Factory: کلاس جدا و ساده
- Factory Method: در کلاس و قابل توسعه با inheritance

> **نکته کاربردی**: برای ساخت ساده از Factory و برای ساخت با منطق از Factory Method استفاده کنید.

### ۱۰۳. Singleton Pattern چیست و چه معایبی دارد؟

**مفهوم**: اطمینان از اینکه یک کلاس فقط **یک نمونه** (instance) داشته باشد.

**پیاده‌سازی در PHP**:
```php
class Database {
    private static $instance = null;
    
    private function __construct() {} // جلوگیری از new
    
    public static function getInstance() {
        if (self::$instance === null) {
            self::$instance = new self();
        }
        return self::$instance;
    }
    
    // متدهای دیگر...
}
```

**معایب**:
1. **تست‌پذیری ضعیف**: state را به اشتراک می‌گذارد
2. **مخفی‌سازی وابستگی**: وابستگی‌ها پنهان می‌شوند
3. **مشکل در توسعه**: انعطاف‌پذیری کم
4. **وابستگی پنهان**: کلاس‌ها از طریق متد استاتیک وابسته می‌شوند
5. **تغییر سخت**: اگر به چند نمونه نیاز باشد، تغییر دشوار است

**جایگزین‌ها**:
- استفاده از Service Container (مثل Laravel)
- Dependency Injection با Singleton در Container

> **نکته کاربردی**: Singleton را با احتیاط و فقط در موارد ضروری استفاده کنید.

### ۱۰۴. Repository Pattern چیست؟

**مفهوم**: لایه انتزاع بین منطق کسب‌وکار و دیتابیس.

**ساختار**:
```
Controller → Service → Repository → Database
```

**مثال**:
```php
// Interface
interface UserRepositoryInterface {
    public function findById($id);
    public function findByEmail($email);
    public function save(User $user);
    public function delete($id);
}

// پیاده‌سازی با Eloquent
class EloquentUserRepository implements UserRepositoryInterface {
    public function findById($id) {
        return User::find($id);
    }
    
    public function save(User $user) {
        return $user->save();
    }
}

// استفاده در Service
class UserService {
    public function __construct(
        private UserRepositoryInterface $repository
    ) {}
    
    public function getUser($id) {
        return $this->repository->findById($id);
    }
}
```

**مزایا**:
- جداسازی لایه دیتابیس
- تست‌پذیری بالا (mock repository)
- تغییر دیتابیس آسان (MySQL → MongoDB)

> **نکته کاربردی**: Repository Pattern در پروژه‌های بزرگ ضروری است.

### ۱۰۵. Observer Pattern چیست؟

**مفهوم**: یک شیء (subject) به observerها اطلاع می‌دهد از تغییرات.

**ساختار**:
```
Subject → (notify) → Observer1, Observer2, Observer3
```

**مثال**:
```php
// Event System در Laravel
class OrderShipped {
    public function __construct(public $order) {}
}

class SendEmailListener {
    public function handle(OrderShipped $event) {
        // ارسال ایمیل
    }
}

class UpdateInventoryListener {
    public function handle(OrderShipped $event) {
        // بروزرسانی موجودی
    }
}

// استفاده
event(new OrderShipped($order));
// همه Listenerها اجرا می‌شوند
```

**کاربردها**:
- سیستم رویداد (Event/Listener)
- WhatsApp, Telegram Notifications
- سیستم‌های مبتنی بر رویداد (Event-driven)

> **نکته کاربردی**: Observer در Laravel با Event/Listener پیاده‌سازی شده است.

### ۱۰۶. Adapter Pattern چه کاربردی دارد؟

**مفهوم**: تبدیل interface یک کلاس به interface دیگر برای سازگاری.

**مثال**:
```php
// سیستم قدیمی
class LegacyPayment {
    public function processPayment($amount, $currency) { /* ... */ }
}

// سیستم جدید
interface PaymentGateway {
    public function pay($amount);
}

// Adapter: تطبیق Legacy با جدید
class LegacyPaymentAdapter implements PaymentGateway {
    private $legacy;
    
    public function __construct(LegacyPayment $legacy) {
        $this->legacy = $legacy;
    }
    
    public function pay($amount) {
        // تبدیل و فراخوانی
        $this->legacy->processPayment($amount, 'USD');
    }
}

// استفاده
$gateway = new LegacyPaymentAdapter(new LegacyPayment());
$gateway->pay(100);
```

**زمان استفاده**:
- یکپارچه‌سازی با سیستم‌های قدیمی (Legacy)
- استفاده از کتابخانه‌های با interface متفاوت
- تبدیل داده‌ها بین سیستم‌ها

> **نکته کاربردی**: Adapter برای کدهای Legacy و یکپارچه‌سازی حیاتی است.

### ۱۰۷. Decorator Pattern چیست؟

**م概念**: افزودن رفتار جدید به اشیاء به صورت **پویا** بدون تغییر کلاس اصلی.

**مثال**:
```php
interface Coffee {
    public function cost();
    public function description();
}

class SimpleCoffee implements Coffee {
    public function cost() { return 5; }
    public function description() { return "Simple Coffee"; }
}

// Decorator Base
abstract class CoffeeDecorator implements Coffee {
    protected $coffee;
    
    public function __construct(Coffee $coffee) {
        $this->coffee = $coffee;
    }
}

// Concrete Decorators
class MilkDecorator extends CoffeeDecorator {
    public function cost() { return $this->coffee->cost() + 2; }
    public function description() { return $this->coffee->description() . " + Milk"; }
}

class SugarDecorator extends CoffeeDecorator {
    public function cost() { return $this->coffee->cost() + 1; }
    public function description() { return $this->coffee->description() . " + Sugar"; }
}

// استفاده
$coffee = new SimpleCoffee();
$coffee = new MilkDecorator($coffee);
$coffee = new SugarDecorator($coffee);
echo $coffee->cost(); // 8
echo $coffee->description(); // "Simple Coffee + Milk + Sugar"
```

**کاربرد**: Middleware در Laravel، Streams در PHP

> **نکته کاربردی**: Decorator برای افزودن قابلیت‌های اختیاری بدون تغییر کلاس عالی است.

### ۱۰۸. تفاوت Design Pattern و Design Principle چیست؟

**مفهوم**: دو سطح مختلف در طراحی نرم‌افزار.

**Design Principles (اصول طراحی)**:
- **سطح بالا** (high-level) و عمومی
- راهنماهای کلی برای طراحی خوب
- مثال: SOLID, DRY, KISS, YAGNI
- می‌گویند **چه کاری** انجام دهیم

**Design Patterns (الگوهای طراحی)**:
- **سطح پایین** (low-level) و اختصاصی
- راه‌حل‌های مشخص برای مسائل تکراری
- مثال: Factory, Singleton, Observer
- می‌گویند **چگونه** انجام دهیم

**مقایسه**:
```
Principles: "به Interfaceها وابسته باشید" (راهنما)
Patterns:   "از Factory Pattern برای ساخت اشیاء استفاده کنید" (راه‌حل)
```

**ارتباط**:
- Principles رعایت شوند → Patterns بهتر کار می‌کنند
- Patterns پیاده‌سازی Principles هستند

> **نکته کاربردی**: Principles را درک کنید، Patterns را برای حل مسائل خاص انتخاب کنید.

## 🔄 بخش ۱۳: GIT

### ۱۰۹. تفاوت Merge و Rebase چیست؟

**مفهوم**: دو روش ترکیب تغییرات از دو branch.

**Merge**:
- یک **commit جدید** ایجاد می‌کند (merge commit)
- تاریخچه (history) را حفظ می‌کند
- غیرمخرب (non-destructive)
- برای branches عمومی

```
main:    A---B---C
                \
feature:         D---E
→ Merge → main: A---B---C---F (merge commit)---D---E
```

**Rebase**:
- تاریخچه را **بازنویسی** می‌کند
- commit‌های feature را به بالای main منتقل می‌کند
- تاریخچه خطی و تمیز
- خطرناک برای branches مشترک

```
main:    A---B---C
                \
feature:         D---E
→ Rebase → feature: A---B---C---D'---E' (تاریخچه خطی)
```

**کی استفاده**:
- **Merge**: برای branches عمومی و مشترک
- **Rebase**: برای branches شخصی و قبل از push

> **نکته کاربردی**: از Rebase برای branches شخصی، از Merge برای branches مشترک استفاده کنید.

### ۱۱۰. Git Flow چیست؟

**مفهوم**: مدل branching محبوب برای مدیریت پروژه‌ها.

**Branches اصلی**:
1. **main/master**: کد stable و تولید (production)
2. **develop**: کد توسعه (integration)

**Branches کمکی**:
3. **feature/***: برای توسعه قابلیت‌های جدید (از develop جدا می‌شود)
4. **release/***: برای آماده‌سازی نسخه جدید (از develop جدا می‌شود)
5. **hotfix/***: برای رفع باگ‌های بحرانی در production (از main جدا می‌شود)

**جریان کار**:
```
feature/* → develop → release/* → main
hotfix/* → main → develop
```

**مزایا**:
- ساختار مشخص
- مناسب برای پروژه‌های با نسخه‌بندی
- کنترل کامل بر انتشار

> **نکته کاربردی**: Git Flow برای پروژه‌های با نسخه‌بندی مناسب است.

### ۱۱۱. تفاوت git fetch و git pull چیست؟

**مفهوم**: دو روش دریافت تغییرات از remote.

**git fetch**:
- فقط **دریافت** تغییرات از remote
- branchهای محلی **به‌روز نمی‌شوند**
- امن (غیرمخرب)
```bash
git fetch origin
# تغییرات در origin/main دانلود می‌شود
# ولی main محلی تغییری نمی‌کند
```

**git pull**:
- **دریافت + merge** تغییرات
- branch محلی به‌روز می‌شود
- معادل `git fetch + git merge`
```bash
git pull origin main
# تغییرات دانلود می‌شود + با main محلی merge می‌شود
```

**کی استفاده**:
- `fetch`: برای دیدن تغییرات قبل از اعمال
- `pull`: برای به‌روز کردن سریع branch

> **نکته کاربردی**: قبل از pull، از `fetch` برای بررسی تغییرات استفاده کنید.

### ۱۱۲. Merge Conflict چطور حل می‌شود؟

**مفهوم**: زمانی که Git نمی‌تواند تغییرات را به‌طور خودکار ترکیب کند.

**مراحل حل**:

1. **تشخیص**: Git پیام conflict می‌دهد
2. **مشاهده**: `git status` فایل‌های conflict را نشان می‌دهد
3. **ویرایش**: فایل‌ها را باز کنید و تصمیم بگیرید

**فایل conflict**:
```
<<<<<<< HEAD (برنچ فعلی)
$amount = 100;
======= (تغییرات دیگر)
$amount = 150;
>>>>>>> feature-branch (برنچ دیگر)
```

4. **حل**:
   - انتخاب یکی از دو تغییر
   - یا ترکیب هر دو
   - حذف `<<<<<<<`, `=======`, `>>>>>>>`
5. **مرحله‌بندی**: `git add <file>`
6. **کامیت**: `git commit` (یا `git merge --continue`)

**ابزارها**:
- `git mergetool` (باز کردن GUI)
- Editorهای کد (VS Code, PHPStorm)

> **نکته کاربردی**: قبل از pull، تغییرات خود را commit کنید تا conflict قابل حل باشد.

### ۱۱۳. تفاوت Branch و Tag چیست؟

**مفهوم**: دو نوع pointer در Git.

**Branch**:
- **پویا** (متغیر)
- با هر commit جدید حرکت می‌کند
- برای توسعه و کارهای در حال انجام
- قابل حذف و ایجاد

```
main → A---B---C (به روز می‌شود)
```

**Tag**:
- **ثابت** (غیرمتغیر)
- به یک commit خاص اشاره می‌کند
- برای نشان‌گذاری نسخه‌ها (v1.0, v2.0)
- معمولاً حذف نمی‌شود

```
v1.0 → A (همیشه به A اشاره می‌کند)
main → A---B---C (ادامه می‌دهد)
```

**انواع Tag**:
- **Lightweight**: فقط اشاره‌گر
- **Annotated**: با پیام، تاریخ، امضا

```bash
git tag v1.0              # Lightweight
git tag -a v1.0 -m "Version 1.0"  # Annotated
```

> **نکته کاربردی**: از Tag برای نسخه‌های پایدار و انتشار استفاده کنید.

### ۱۱۴. git cherry-pick چه کاربردی دارد؟

**مفهوم**: اعمال یک commit خاص از یک branch به branch دیگر.

**مثال**:
```bash
git checkout main
git cherry-pick abc123  # commit را به main اضافه می‌کند
```

**زمان استفاده**:
1. **تصحیح سریع**: یک commit از branch دیگر را به production بیاورید
2. **انتخابی**: فقط بعضی commit‌ها را انتقال دهید (نه کل branch)
3. **لغو تغییرات**: اعمال یک commit معکوس
4. **Backporting**: اعمال تغییرات به نسخه قدیمی‌تر

**مثال واقعی**:
```bash
# bug fix در branch feature
git checkout feature
git commit -m "Fix security bug"
# فقط این commit به main برود
git checkout main
git cherry-pick abc123
```

**مزایا**:
- انتخاب commit‌های خاص
- بدون نیاز به merge کامل

**معایب**:
- ممکن است conflict ایجاد کند
- تاریخچه تکراری

> **نکته کاربردی**: از cherry-pick برای اصلاحات بحرانی در production استفاده کنید.

### ۱۱۵. تفاوت git reset و git revert چیست؟

**مفهوم**: دو روش برای لغو تغییرات با رویکردهای متفاوت.

**git reset**:
- **بازگردانی** به commit قبلی
- **حذف** commit‌ها از تاریخچه
- **مخرب** (history را تغییر می‌دهد)
- سه حالت: `--soft`, `--mixed`, `--hard`

```bash
git reset --hard HEAD~3  # 3 commit آخر حذف می‌شود
```

**git revert**:
- **ایجاد commit جدید** برای معکوس کردن تغییرات
- **حفظ** تاریخچه
- **ایمن** (غیرمخرب)
- مناسب برای branches مشترک

```bash
git revert abc123  # commit جدید برای undo ایجاد می‌کند
```

**مقایسه**:

| Reset | Revert |
|-------|--------|
| حذف commit‌ها | ایجاد commit معکوس |
| تاریخچه تغییر می‌کند | تاریخچه حفظ می‌شود |
| خطرناک برای shared | امن برای shared |
| محلی (local) | قابل push |

> **نکته کاربردی**: در branches مشترک از `revert` و در local از `reset` استفاده کنید.

### ۱۱۶. Squash Commit چیست و چه زمانی استفاده می‌شود؟

**مفهوم**: ترکیب چند commit در یک commit واحد.

**چرا**:
- تاریخچه تمیزتر
- راحت‌تر برای Code Review
- کاهش noise

**روش‌ها**:

1. **Interactive Rebase**:
```bash
git rebase -i HEAD~5  # 5 commit آخر
# تغییر "pick" به "squash" برای commit‌هایی که می‌خواهیم ترکیب شوند
```

2. **Merge with Squash**:
```bash
git merge --squash feature-branch
git commit -m "Add new feature"
```

**زمان استفاده**:
- قبل از merge به develop/main
- برای feature branches با commitهای کوچک
- برای پاک کردن commitهای آزمایشی

**مثال**:
```
قبل: feat1, fix-typo, tests, refactor, feat2
بعد (squash): Add user authentication feature
```

> **نکته کاربردی**: قبل از merge، commit‌های خود را squash کنید تا تاریخچه تمیز بماند.

## 🐳 بخش ۱۴: Docker

### ۱۲۰. تفاوت Image و Container چیست؟

**مفهوم**: دو مفهوم بنیادی در Docker.

**Image (تصویر)**:
- **قالب** (template) فقط خواندنی (read-only)
- شامل کد، runtime، کتابخانه‌ها، تنظیمات
- استاتیک (static)
- ساخته شده با `docker build`

**Container (ظرف)**:
- **نمونه اجرایی** از Image
- شامل لایه **قابل نوشتن** (writable layer)
- داینامیک (dynamic)
- اجرا شده با `docker run`

**مقایسه**:
```
Image = کلاس (Class)
Container = شیء (Object)
```

**مثال**:
```bash
docker build -t my-app .        # ساخت Image
docker run my-app               # ایجاد Container از Image
```

> **نکته کاربردی**: یک Image می‌تواند چندین Container داشته باشد.

### ۱۲۱. Dockerfile چیست و چه بخش‌های اصلی دارد؟

**مفهوم**: فایل دستورالعمل برای ساخت Docker Image.

**ساختار اصلی**:
```dockerfile
# 1. Base Image
FROM php:8.2-fpm

# 2. Environment Variables
ENV APP_ENV=production

# 3. Working Directory
WORKDIR /var/www/html

# 4. Copy Files
COPY . .

# 5. Install Dependencies
RUN apt-get update && apt-get install -y \
    git \
    zip \
    && docker-php-ext-install pdo_mysql

# 6. Run Commands
RUN composer install --no-dev

# 7. Port
EXPOSE 9000

# 8. Command
CMD ["php-fpm"]
```

**بخش‌های مهم**:
- **FROM**: تصویر پایه
- **RUN**: اجرای دستور در زمان ساخت
- **COPY/ADD**: کپی فایل‌ها به Image
- **WORKDIR**: تنظیم دایرکتوری کاری
- **ENV**: تنظیم متغیرهای محیطی
- **CMD/ENTRYPOINT**: دستور اجرایی
- **EXPOSE**: پورت‌های باز

> **نکته کاربردی**: دستورات را مرتب کنید تا از لایه‌بندی بهینه استفاده کنید.

### ۱۲۲. docker-compose چه کاربردی دارد؟

**مفهوم**: ابزاری برای تعریف و اجرای **چندین Container** با هم.

**مثال docker-compose.yml**:
```yaml
version: '3.8'

services:
  app:
    build:
      context: .
      dockerfile: Dockerfile
    volumes:
      - .:/var/www/html
    ports:
      - "8000:8000"
    environment:
      - APP_ENV=local
    depends_on:
      - db
      - redis

  db:
    image: mysql:8.0
    environment:
      MYSQL_DATABASE: laravel
      MYSQL_ROOT_PASSWORD: secret
    volumes:
      - db_data:/var/lib/mysql
    ports:
      - "3306:3306"

  redis:
    image: redis:alpine
    ports:
      - "6379:6379"

  nginx:
    image: nginx:alpine
    volumes:
      - .:/var/www/html
      - ./nginx.conf:/etc/nginx/conf.d/default.conf
    ports:
      - "80:80"
    depends_on:
      - app

volumes:
  db_data:
```

**کاربردها**:
- محیط توسعه یکپارچه
- اجرای چند سرویس (Laravel + MySQL + Redis + Nginx)
- مدیریت وابستگی‌ها

> **نکته کاربردی**: `docker-compose up -d` برای اجرا در پس‌زمینه.

### ۱۲۳. Volume در Docker چیست و چرا لازم است؟

**مفهوم**: مکانیزمی برای ذخیره‌سازی داده‌ها و به اشتراک‌گذاری فایل‌ها بین Container و Host.

**نیاز**: Containerها **ephemeral** (موقتی) هستند و داده‌ها با حذف Container از بین می‌روند.

**انواع Volume**:
1. **Named Volume**: مدیریت شده توسط Docker
```yaml
volumes:
  db_data:  # تعریف
# استفاده
services:
  db:
    volumes:
      - db_data:/var/lib/mysql
```

2. **Bind Mount**: دایرکتوری Host را mount می‌کند
```yaml
volumes:
  - .:/var/www/html  # کد در Host تغییر کند، Container هم تغییر می‌کند
```

3. **Anonymous Volume**: بدون نام (توسط Docker مدیریت)

**مزایا**:
- Persistence داده‌ها
- به‌اشتراک‌گذاری بین Containerها
- محیط توسعه (تغییرات instant)

> **نکته کاربردی**: برای دیتابیس از Named Volume و برای کد از Bind Mount استفاده کنید.

### ۱۲۴. تفاوت Docker Network های مختلف چیست؟

**مفهوم**: شبکه‌های مختلف برای ارتباط Containerها.

**انواع**:
1. **bridge** (پیش‌فرض):
   - شبکه داخلی برای Containerهای یک Host
   - ایزوله از Host
   - هر Container IP خود را دارد

2. **host**:
   - استفاده از شبکه Host
   - Portها مستقیماً روی Host هستند
   - پرسرعت اما کمتر امن

3. **none**:
   - بدون شبکه
   - کاملاً ایزوله
   - برای Containerهای خاص

4. **overlay**:
   - برای Swarm و چندین Host
   - ارتباط بین Hostها

5. **macvlan**:
   - اختصاص MAC آدرس به Container
   - مانند یک دستگاه فیزیکی در شبکه

**انتخاب**:
- **bridge**: برای محیط توسعه
- **host**: برای performance بحرانی
- **overlay**: برای Clusterها

> **نکته کاربردی**: از bridge برای توسعه و overlay برای production استفاده کنید.

### ۱۲۵. Multi-stage Build چیست و چه مزیتی دارد؟

**مفهوم**: استفاده از چندین مرحله در Dockerfile برای کاهش حجم Image نهایی.

**مثال**:
```dockerfile
# مرحله 1: Build (سنگین)
FROM composer:2 AS builder
WORKDIR /app
COPY composer.json composer.lock ./
RUN composer install --no-dev

# مرحله 2: Runtime (سبک)
FROM php:8.2-fpm-alpine
WORKDIR /var/www/html
COPY --from=builder /app/vendor /var/www/html/vendor
COPY . .
RUN docker-php-ext-install pdo_mysql

CMD ["php-fpm"]
```

**مزایا**:
1. **حجم کمتر**: فایل‌های build حذف می‌شوند
2. **امن‌تر**: ابزارهای build در Image نهایی نیستند
3. **سریع‌تر**: لایه‌های کمتر

**کاربرد**:
- Build و کامپایل کد (Node.js, Go, Rust)
- حذف dependencyهای توسعه

> **نکته کاربردی**: از Multi-stage برای کاهش حجم Image و افزایش امنیت استفاده کنید.

## 🌍 بخش ۱۵: Nginx

### ۱۲۷. Nginx چه نقشی به عنوان Reverse Proxy دارد؟

**مفهوم**: Nginx به عنوان واسط بین کلاینت و سرورهای پشتی (backend) عمل می‌کند.

**نحوه کار**:
```
Client → Nginx (Reverse Proxy) → Backend Server (PHP-FPM, Node, etc.)
       ← Nginx (Response) ← Backend Server
```

**مزایا**:
1. **Load Balancing**: توزیع ترافیک بین چند سرور
2. **SSL Termination**: مدیریت SSL در یک نقطه
3. **Caching**: کش کردن پاسخ‌ها
4. **Security**: مخفی کردن جزئیات سرورهای پشتی
5. **Compression**: فشرده‌سازی پاسخ‌ها (Gzip)
6. **Rate Limiting**: محدودیت درخواست

**مثال**:
```nginx
server {
    listen 80;
    server_name example.com;
    
    location / {
        proxy_pass http://backend_servers;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

> **نکته کاربردی**: Reverse Proxy بهترین راه برای توزیع بار و افزایش امنیت است.

### ۱۲۸. تفاوت Nginx و Apache چیست؟

**مفهوم**: دو وب سرور محبوب با معماری‌های متفاوت.

| ویژگی | Nginx | Apache |
|-------|-------|--------|
| **معماری** | Event-driven (غیرمسدود) | Process-based (مسدود) |
| **Static Files** | ✅ بسیار سریع (async) | ✅ سریع اما با حافظه بیشتر |
| **Dynamic Content** | ✅ (با PHP-FPM) | ✅ (با mod_php) |
| **حافظه** | کمتر (با اتصالات زیاد) | بیشتر (هر connection یک process) |
| **مدولار** | مدول‌های پویا (از 1.9.11) | مدول‌های استاتیک و پویا |
| **پیکربندی** | `.conf` (کم‌تر) | `.htaccess` (در هر دایرکتوری) |
| **کاربرد اصلی** | Reverse Proxy, Static, Load Balancer | Web Server با ماژول‌های فراوان |

**زمان استفاده**:
- **Nginx**: برای Load Balancing و Static Files عالی است
- **Apache**: برای hosting با `mod_php` و .htaccess

> **نکته کاربردی**: امروزه ترکیب Nginx (Reverse Proxy) + Apache (Backend) یا Nginx + PHP-FPM رایج است.

### ۱۲۹. Load Balancing در Nginx چطور تنظیم می‌شود؟

**مفهوم**: توزیع ترافیک بین چندین Backend Server.

**تنظیم**:
```nginx
upstream backend_servers {
    # متدهای Load Balancing
    # 1. Round Robin (پیش‌فرض)
    server 192.168.1.10:8000;
    server 192.168.1.11:8000;
    server 192.168.1.12:8000;
    
    # 2. Least Connections
    least_conn;
    
    # 3. IP Hash (همیشه به یک سرور)
    ip_hash;
    
    # 4. Weighted
    server 192.168.1.10:8000 weight=3;  # 3 برابر بیشتر
    server 192.168.1.11:8000 weight=1;
    
    # Health Check (keepalive)
    keepalive 32;
}

server {
    location / {
        proxy_pass http://backend_servers;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
    }
}
```

**متدها**:
1. **Round Robin**: توزیع مساوی (پیش‌فرض)
2. **Least Connections**: به سرور با کمترین اتصال
3. **IP Hash**: بر اساس IP کلاینت (Sticky Session)
4. **Weighted**: بر اساس وزن (برای سرورهای قوی‌تر)

> **نکته کاربردی**: برای Sticky Session از `ip_hash` استفاده کنید.

### ۱۳۰. Nginx چطور با PHP-FPM ارتباط برقرار می‌کند؟

**مفهوم**: دو روش ارتباط Nginx و PHP-FPM.

**۱. Unix Socket** (سریع‌تر، فقط local):
```nginx
location ~ \.php$ {
    fastcgi_pass unix:/var/run/php/php8.2-fpm.sock;
    include fastcgi_params;
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
}
```

**۲. TCP/IP** (قابل استفاده در شبکه):
```nginx
location ~ \.php$ {
    fastcgi_pass 127.0.0.1:9000;
    include fastcgi_params;
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
}
```

**پارامترهای مهم**:
- `fastcgi_pass`: آدرس PHP-FPM
- `fastcgi_param SCRIPT_FILENAME`: مسیر فایل PHP
- `include fastcgi_params`: تنظیمات پیش‌فرض
- `fastcgi_read_timeout`: زمان timeout

**بهترین روش**: استفاده از Unix Socket برای سرعت بالاتر و امنیت بیشتر (زمانی که در یک Host هستند).

> **نکته کاربردی**: در Docker معمولاً از TCP استفاده می‌شود چون Containerها جدا هستند.

### ۱۳۱. Zero-downtime Deployment با Nginx چطور انجام می‌شود؟

**مفهوم**: به‌روزرسانی برنامه بدون قطع سرویس.

**روش Blue-Green Deployment**:
```nginx
upstream app {
    # نسخه فعلی (Blue)
    server 127.0.0.1:8000;
}

server {
    listen 80;
    server_name example.com;
    
    location / {
        proxy_pass http://app;
        proxy_set_header Host $host;
    }
}
```

**مراحل**:
1. نسخه جدید (Green) را روی پورت 8001 deploy کنید
2. تست کنید (با curl یا Postman)
3. Nginx را reload کنید:
```bash
# تغییر upstream به پورت جدید
upstream app {
    server 127.0.0.1:8001;  # Green
}
# Reload بدون قطع
nginx -s reload
```
4. نسخه قدیمی (Blue) را حذف کنید

**متدهای دیگر**:
- **Using Symbolic Link**: تغییر `root` به نسخه جدید
- **Using Docker Swarm**: Rolling Update
- **Kubernetes**: Rolling Update

**مزایا**:
- بدون قطع سرویس
- قابلیت Rollback سریع (با reload به نسخه قدیمی)

> **نکته کاربردی**: همیشه از `nginx -s reload` برای اعمال تغییرات بدون قطع استفاده کنید.

### ۱۳۲. SSL Termination در Nginx چیست؟

**مفهوم**: رمزگشایی HTTPS در Nginx و ارسال ترافیک HTTP به Backend.

**پیکربندی**:
```nginx
server {
    listen 443 ssl http2;
    server_name example.com;
    
    # SSL Certificate
    ssl_certificate /etc/nginx/ssl/example.crt;
    ssl_certificate_key /etc/nginx/ssl/example.key;
    
    # SSL Settings (بهترین practice)
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;
    
    # Redirect HTTP به HTTPS
    location / {
        proxy_pass http://backend;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

server {
    listen 80;
    server_name example.com;
    return 301 https://$server_name$request_uri;  # Redirect
}
```

**مزایا**:
1. **متمرکز کردن SSL**: مدیریت در یک نقطه
2. **کاهش بار**: Backend نیازی به SSL ندارد
3. **امنیت بهتر**: تنظیمات SSL در یک جا
4. **HTTP/2**: پشتیبانی در Nginx

**ابزارها**: Let's Encrypt برای SSL رایگان

> **نکته کاربردی**: همیشه از `X-Forwarded-*` headers برای اطلاع Backend استفاده کنید.

### ۱۳۳. Rate Limiting در Nginx چطور پیکربندی می‌شود؟

**مفهوم**: محدودیت تعداد درخواست‌ها برای جلوگیری از حمله و حفظ عملکرد.

**تنظیم**:
```nginx
# تعریف zone برای ذخیره‌سازی state
http {
    limit_req_zone $binary_remote_addr zone=api_limit:10m rate=10r/s;
    limit_req_zone $binary_remote_addr zone=web_limit:10m rate=30r/m;
    
    server {
        location /api/ {
            limit_req zone=api_limit burst=20 nodelay;
            proxy_pass http://backend;
        }
        
        location / {
            limit_req zone=web_limit burst=5;
            proxy_pass http://backend;
        }
    }
}
```

**پارامترها**:
- `limit_req_zone`: تعریف zone با اندازه و نرخ
- `$binary_remote_addr`: کلید بر اساس IP
- `rate`: تعداد درخواست در ثانیه (r/s) یا دقیقه (r/m)
- `burst`: میزان پرش (overage) مجاز
- `nodelay`: درخواست‌های burst را بدون تاخیر ارسال می‌کند

**مثال دیگر**:
```nginx
# محدودیت برای API
limit_req_zone $binary_remote_addr zone=api:10m rate=5r/s;

location /api/ {
    limit_req zone=api burst=10;
    # ۵ درخواست در ثانیه، با burst ۱۰
}
```

**پاسخ**: `HTTP 503 Service Unavailable` یا `HTTP 429 Too Many Requests`

> **نکته کاربردی**: Rate Limiting را در Nginx و Laravel هر دو تنظیم کنید.

## ⚙️ بخش ۱۶: PHP-FPM

### ۱۳۴. PHP-FPM چیست و چه تفاوتی با mod_php دارد؟

**مفهوم**: PHP FastCGI Process Manager - یک پیاده‌سازی از FastCGI برای PHP.

**PHP-FPM**:
- مستقل از وب سرور (standalone)
- مدیریت **Poolهای فرایند** (process pools)
- ارتباط با Nginx/Apache از طریق FastCGI
- مقیاس‌پذیر و کارآمد

**mod_php**:
- ماژول داخل Apache (embedded)
- هر درخواست یک فرایند جدید Apache
- مصرف حافظه بالا
- محدود به Apache

**مقایسه**:

| ویژگی | PHP-FPM | mod_php |
|-------|---------|---------|
| **معماری** | مستقل | داخل Apache |
| **مدیریت** | Process Pool | Process per request |
| **حافظه** | بهینه (تعداد مشخص) | بالا (برای هر درخواست) |
| **مقیاس‌پذیری** | ✅ بالا | ❌ محدود |
| **زمان** | FastCGI | Embeded |

> **نکته کاربردی**: برای محیط‌های تولید از PHP-FPM استفاده کنید (بهتر و سریع‌تر).

### ۱۳۵. تفاوت Pool های مختلف در PHP-FPM چیست؟

**مفهوم**: هر Pool مجموعه‌ای از فرایندهای PHP با تنظیمات خاص.

**تعریف**:
```ini
[www]  ; نام Pool
user = www-data
group = www-data
listen = /var/run/php/php8.2-fpm.sock

[backend]  ; Pool دیگر
user = backend
group = backend
listen = 127.0.0.1:9001
```

**چرا چندین Pool**:
1. **جداسازی اپلیکیشن‌ها**: هر وب‌سایت pool خودش را دارد
2. **تنظیمات متفاوت**: حافظه، timeout، تعداد فرایند
3. **اولویت‌بندی**: API pool با منابع بیشتر
4. **ایزوله‌سازی**: یک اپلیکیشن مشکل‌دار اپلیکیشن دیگر را تحت تأثیر قرار نمی‌دهد

**پیکربندی**:
```nginx
# Nginx برای هر pool
location / {
    fastcgi_pass unix:/var/run/php/php8.2-fpm.sock;  # Pool www
}

location /api/ {
    fastcgi_pass 127.0.0.1:9001;  # Pool backend
}
```

> **نکته کاربردی**: برای هر وب‌سایت یا سرویس یک Pool مجزا ایجاد کنید.

### ۱۳۶. تنظیمات pm.max_children، pm.start_servers چه کاربردی دارند؟

**مفهوم**: تنظیمات مدیریت Process Manager در PHP-FPM.

**pm** (Process Manager):
```ini
pm = dynamic  ; حالت مدیریت

; تنظیمات
pm.max_children = 50          ; حداکثر فرایندها
pm.start_servers = 5          ; فرایندهای اولیه
pm.min_spare_servers = 5      ; حداقل فرایندهای آماده
pm.max_spare_servers = 35     ; حداکثر فرایندهای آماده
```

**معانی**:
- **pm.max_children**: حداکثر تعداد فرایندهای PHP که می‌توانند همزمان اجرا شوند
  - اگر ۵۰ باشد → حداکثر ۵۰ درخواست همزمان
  - خیلی کم → Queue می‌شود
  - خیلی زیاد → حافظه تمام می‌شود

- **pm.start_servers**: تعداد فرایندهای اولیه در شروع PHP-FPM
  - برای کاهش زمان شروع

- **pm.min_spare_servers**: حداقل فرایندهای آماده (idle)
  - کمتر از این → فرایند جدید ایجاد می‌شود

- **pm.max_spare_servers**: حداکثر فرایندهای آماده
  - بیشتر از این → فرایندها بسته می‌شوند

> **نکته کاربردی**: برای ۲GB RAM: max_children ≈ ۵۰, ۴GB: ۱۰۰ (بسته به اپلیکیشن).

### ۱۳۷. تفاوت حالت‌های dynamic، static و ondemand در PHP-FPM چیست؟

**مفهوم**: سه روش مدیریت فرایندهای PHP.

**۱. dynamic** (پیش‌فرض):
- تعداد فرایندها **متغیر** بر اساس بار
- بین min_spare_servers و max_children
- مناسب برای اکثر برنامه‌ها
```ini
pm = dynamic
pm.max_children = 50
pm.start_servers = 5
pm.min_spare_servers = 5
pm.max_spare_servers = 35
```

**۲. static**:
- تعداد فرایندها **ثابت**
- همیشه max_children فرایند فعال
- کاربرد: بار ثابت و پیش‌بینی‌پذیر
```ini
pm = static
pm.max_children = 20  ; همیشه ۲۰ فرایند
```

**۳. ondemand**:
- فرایندها **بر اساس درخواست** ایجاد می‌شوند
- بعد از idle بسته می‌شوند (با process_idle_timeout)
- کاربرد: بار کم و متغیر
```ini
pm = ondemand
pm.max_children = 50
pm.process_idle_timeout = 10s
```

**انتخاب**:
- **dynamic**: اکثر موارد (تعادل بین سرعت و حافظه)
- **static**: بار ثابت (APIها)
- **ondemand**: بار کم و متغیر (ادمین پنل)

> **نکته کاربردی**: از dynamic استفاده کنید تا بهینه باشد.

### ۱۳۸. Unix Socket در مقابل TCP در ارتباط Nginx و PHP-FPM چه تفاوتی دارد؟

**مفهوم**: دو روش ارتباطی با مزایا و معایب.

**Unix Socket**:
- فایل محلی (`/var/run/php/php8.2-fpm.sock`)
- فقط در **همان Host** قابل استفاده
- سریع‌تر و با **Overhead کمتر**
- امن‌تر (دسترسی محدود به فایل)
```nginx
fastcgi_pass unix:/var/run/php/php8.2-fpm.sock;
```

**TCP/IP**:
- پورت شبکه (`127.0.0.1:9000`)
- قابل استفاده **در شبکه** (بین Hostها)
- کندتر (TCP overhead)
- نیاز به تنظیمات شبکه
```nginx
fastcgi_pass 127.0.0.1:9000;
```

**مقایسه**:

| ویژگی | Unix Socket | TCP |
|-------|-------------|-----|
| **سرعت** | ✅ سریع‌تر | ❌ کندتر |
| **امنیت** | ✅ بالاتر (file permissions) | ❌ نیاز به firewall |
| **مقیاس‌پذیری** | ❌ فقط محلی | ✅ چند Host |
| **پیکربندی** | ساده | پیچیده‌تر |
| **استفاده** | توسعه/تولید تک سرور | چندین سرور |

> **نکته کاربردی**: در یک Host از Unix Socket استفاده کنید. در Docker معمولاً از TCP استفاده می‌شود.

### ۱۳۹. چطور مشکلات Performance مربوط به PHP-FPM را دیباگ می‌کنید؟

**مفاهیم و روش‌ها**:

**۱. بررسی Logها**:
```bash
# PHP-FPM Error Log
tail -f /var/log/php8.2-fpm.log

# Slow Log (کندترین درخواست‌ها)
tail -f /var/log/php8.2-fpm.slow.log
```

**فعال کردن Slow Log**:
```ini
request_slowlog_timeout = 2s
slowlog = /var/log/php8.2-fpm.slow.log
```

**۲. تنظیمات pm**:
- بررسی `pm.max_children` (به اندازه کافی؟)
- بررسی حافظه (RAM) و تنظیم `pm` مناسب
- افزایش `pm.max_children` اگر Queue می‌شود

**۳. بررسی Status**:
```ini
pm.status_path = /status
```
```nginx
location /status {
    fastcgi_pass unix:/var/run/php/php8.2-fpm.sock;
    include fastcgi_params;
}
```

**۴. ابزارهای Monitoring**:
- **htop**: بررسی مصرف CPU/Memory
- **New Relic**: performance monitoring
- **Laravel Debugbar**: برای کوئری‌های کند

**۵. راه‌حل‌ها**:
- افزایش `pm.max_children`
- تغییر به `static` اگر بار ثابت است
- بهینه‌سازی کد (کوئری‌ها، کش)
- اضافه کردن سرور (Horizontal Scaling)

> **نکته کاربردی**: Slow Log را فعال کنید تا متدهای کند را پیدا کنید.
